- 상태: 초안. 전달 자료가 확정 UI와 출시 1차 기본값으로 구분한 내용을 옮겼으며, 저장소 구현과 서버 적용 여부는 확인하지 않았습니다.

## 목적과 근거 해석

이별에 관한 이야기를 익명으로 읽고 남기는 경험에서, 계정 권한·콘텐츠 처리·복귀 규칙을 일관되게 적용합니다. 익명은 공개 화면에서의 표시 방식입니다. 서버의 사용자 식별까지 없애는 정책은 아닙니다.

전달 자료는 예외 처리·저장 범위·정렬·타임아웃 중 일부를 2026-10-20 정리 과정에서 새 기본값으로 정했다고 명시합니다. 이를 과거부터 합의한 정책으로 소급하지 않습니다. 아래의 `UI`, `1차 기본값` 표시는 원문이 밝힌 근거이며, 실제 동작 검증이나 별도 승인 완료를 뜻하지 않습니다. 자료 간 차이는 [제품 범위 문서](../specs/product-overview.md)에서 추적하고, 화면의 구체 규칙 → 공통 규칙 → 원본 설계 메모 순으로 대조합니다.

## D-01 · 첫 방문과 둘러보기

근거는 UI 로그인 안내와 1차 기본값입니다. 글 등록이나 로그인을 피드 접근 조건으로 삼지 않습니다.

- 공유 링크가 없는 첫 일반 진입은 시뮬레이션 3종을 균등 배정합니다. 시작 화면은 `02.01`, `02.06`, `02.11` 중 하나입니다.
- 저장된 미완료 단계가 있으면 이어서 표시합니다. 완료하거나 건너뛰어 둘러본 이력이 있으면 `04.01`로 갑니다.
- 뒤로 가기와 이탈을 허용하고 미완료 진행을 보관합니다. 첫 진입에 별도 랜딩 화면을 추가하지 않습니다. `01.01`은 확정 UI에 없으며 이전 `0-1` 이미지는 참고 자료입니다.
- 공유 링크의 대상 이야기 진입이 시뮬레이션보다 우선합니다.

## D-02 · 초안과 진행 보관

근거는 1차 기본값과 `00-A / DRAFT`입니다. 초안을 실수로 잃지 않게 하되, 계정 사이에 본문이 섞이지 않도록 합니다.

- 로그인 계정별로 같은 브라우저에 초안을 보관합니다. 자동 만료와 기기 간 동기화는 없습니다.
- 입력 변경 후 `500ms` 안에 저장하고, 이탈 전에 저장 성공을 확인합니다. 저장 실패 시 본문을 유지하고 재시도를 허용합니다.
- 초안 삭제는 새로 시작의 명시적 확인, 등록 성공, 로그아웃, 탈퇴 때만 합니다. 미게시 초안이 있는 로그아웃은 삭제 안내와 확인을 거칩니다.
- 시뮬레이션 진행은 브라우저별로 초안과 따로 보관합니다.
- 본문이 있는 작성 화면 이탈은 `03.10`을 거칩니다. 계속 작성하면 편집과 커서를 복원하고, 나중에 쓰기는 저장 확인 후 `04.01`로 이동합니다. 다음 작성 진입은 `03.09`입니다.
- 앱 확장 시 브라우저 저장 범위를 네이티브 저장소에 어떻게 대응할지는 아직 정하지 않았습니다.

## D-03 · 익명과 계정 권한

근거는 확정 UI, 1차 기본값, `00-A / AUTH·RETURN·EMPTY`입니다.

| 동작 | 게스트 접근 | 인증이 필요한 경우의 진입 화면 |
| --- | --- | --- |
| 시뮬레이션, 피드·공개 이야기 읽기, 공유 | 허용 | 해당 없음 |
| 개인 숨김 | 같은 브라우저 범위에서 허용 | 로그인 사용자의 저장 방식은 서버 계약 참조 |
| 글쓰기 | 로그인 필요 | `08.02` |
| 공감·신고·차단 | 로그인 필요 | `08.03` |
| MY | 로그인 필요 | `08.07` |
| 알림 | 로그인 필요 | `05.03` |
| 설정 직접 접근 | 로그인 필요 | `08.01` |

- 공급자 순서는 `Apple → Google → 카카오`입니다. 최초 로그인 또는 현재 필수 약관 버전 미동의 시 이용약관·개인정보 처리방침·만 14세 이상 확인의 필수 3개 동의를 거칩니다. 모두 미선택으로 시작하며 실제 문서 버전과 서버 저장 성공 전에는 보호 기능을 사용할 수 없습니다. 만 14세 이상은 체크 확인이며 생년월일 수집·자동 검증을 추가하지 않습니다(`08.06`). 같은 이메일이라는 이유로 다른 공급자 계정을 클라이언트가 합치지 않습니다.
- 서버도 같은 권한을 검사합니다. 비로그인을 개인 데이터 0건으로 표시하지 않습니다. 인증 필요, 조회 중, 성공 0건, 성공 1건 이상, 실패를 구분합니다.
- 로그인 전 의도를 1회성으로 보관하고 필수 동의 완료 후 권한과 대상 상태를 다시 확인합니다. 글쓰기는 초안 분기, 공감은 원래 목표 상태 1회 적용, 신고는 사유 선택, 차단은 확인 화면, MY·알림은 재조회로 이어집니다.
- 취소·실패 시 후속 액션을 실행하지 않습니다. 공개 확인·신고·차단 같은 확정 동작은 재인증만으로 자동 제출하지 않습니다.
- 세션 만료·계정 변경 후 이전 계정의 초안·MY·알림 캐시를 노출하지 않습니다. 취소하거나 소비한 복귀 의도도 정리합니다.

## INPUT·SUMMARY · 본문과 자동 요약

근거는 `00-A`입니다. 별도 제목 입력은 없습니다.

| ID | 규칙 |
| --- | --- |
| INPUT | `trim` 결과가 비어 있지 않고 원문이 `1–1,000`개의 사용자 인식 문자이면 유효합니다. 본문의 공백과 줄바꿈은 보존합니다. |
| INPUT | 한글 조합 완료 후 검증합니다. 초과 입력·붙여넣기는 `1,000`자까지만 반영하고 안내합니다. 카운터와 서버는 같은 문자 분할 기준을 사용합니다. |
| SUMMARY | 앞뒤 공백 제거 → 줄바꿈·연속 공백을 한 칸으로 정리 → 앞 `20`개의 사용자 인식 문자 발췌 → 남은 내용이 있으면 `…` 추가 순서입니다. 원본 본문은 변경하지 않습니다. |
| SUMMARY | 피드와 MY 제목은 같은 요약값을 씁니다. 미리보기는 한 줄 말줄임이며, 다른 화면은 각 UI의 행 수와 폭을 따릅니다. |

문자 분할 구현과 서버 간 동일성 검증은 [공통 계약](../specs/service-contracts.md)에서 다룹니다. JavaScript 문자열 길이를 정책의 문자 수와 같다고 가정하지 않습니다.

## D-04 · 알림 범위

근거는 기존 UI와 1차 기본값입니다.

- 가입 환영은 계정당 `1회`, 게시글 등록 알림은 성공한 `postId`당 `1회` 생성합니다. 서버가 중복 생성을 막습니다.
- 항목별 읽음 처리 성공 후 읽음 상태와 벨 표시를 갱신합니다.
- 환영 항목은 읽은 뒤에도 목록에 남습니다. 등록 알림은 해당 내 글 상세로 연결합니다.
- 공감·추천 알림은 1차 범위에서 제외합니다. Push 지원 여부는 [운영 설정](launch-operations.md)의 별도 조건을 따릅니다.

## D-05 · 공개와 글의 생명주기

개별 수정·삭제 미제공과 탈퇴 시 제거는 확정 UI를 근거로 합니다. 등록 성공·중복 방지 규칙은 `00-A / REQUEST`, `00-B`, `00-C`를 따릅니다.

- 공개 후 개별 글 수정·삭제 기능은 제공하지 않습니다. 공개 전 편집과 미리보기는 게시글을 생성하지 않습니다.
- 실제 등록 성공과 `postId`를 확인하기 전에는 완료를 표시하거나 초안을 지우지 않습니다.
- 같은 사용자와 `submissionId`로는 게시글이 최대 `1개`입니다. 응답 유실을 실패로 단정하지 않고 기존 시도의 결과를 확인합니다. 결과 불명을 새 게시글 생성으로 회피하지 않습니다.
- 탈퇴는 계정·공개 콘텐츠·공감·알림을 서비스에서 제거한 서버 확인 후 완료합니다. 이전 공유 링크는 열람 불가가 됩니다. 법적 보존·파기 세부는 승인된 개인정보 문서에서 확정할 운영 입력이며, 이 자료에 보존 기간은 없습니다.
- 로그아웃은 서버 글을 보존하면서 현재 세션·푸시 연결과 로컬 개인 데이터를 정리합니다. 완료 뒤 이전 보호 화면을 뒤로 가기로 복원하지 않습니다.

## D-06 · 공유 진입

근거는 1차 기본값입니다.

- 공개 URL은 해당 공개 게시글로 직접 연결하며 계정·세션 정보를 포함하지 않습니다. 읽기에 로그인이 필요하지 않습니다.
- 공개 중단·삭제·차단 대상은 `07.09`로 표시하고 원문을 노출하지 않습니다. 일시 장애는 오류와 재시도로 구분합니다.
- 공유 대상에서 다른 이야기 보기는 `04.01`로 이동합니다. 작성·공감 등 보호 동작에만 인증 분기를 적용합니다.
- 클립보드 복사 성공을 확인한 경우에만 `07.02`를 표시합니다. 실패하면 수동 복사를 허용합니다.

## D-07 · 정렬과 신고·숨김·차단

근거는 확정 UI와 1차 기본값입니다.

- 피드와 MY는 `publishedAt DESC, id DESC` 최신순이며 페이지당 `20개`를 서버 커서로 조회합니다. 같은 ID는 중복 표시하지 않습니다.
- 신고는 `PRIVACY | ABUSE | SPAM | OTHER` 중 하나를 고릅니다. 처음에는 미선택이며 같은 계정과 게시글의 중복 접수를 막습니다. 실패하면 선택한 사유를 보존합니다.
- 숨김은 해당 글, 차단은 해당 작성자의 모든 글에 적용합니다. 성공한 뒤에만 목록에서 제외하고 대상에게 알리지 않습니다. 실패·취소 시 기존 목록을 유지합니다.
- 게스트 숨김은 브라우저 범위입니다. 로그인 사용자의 숨김·차단은 서버 저장 성공으로 판단합니다. 로그인하면 게스트 숨김과 계정 숨김을 합집합으로 병합합니다(`07.05-F1`). 병합·숨김 목록 조회의 실제 API는 원문 공통 계약에 없어 서버 합의가 필요합니다.
- 숨김·차단 해제 UI와 추가 정렬은 제외합니다. 서버가 비공개 원문을 내려주고 클라이언트만 가리는 방식은 허용하지 않습니다.

## SOUND · 소리 선택

근거는 `00-A`입니다. 기본은 음소거이며 사용자의 직접 탭에서만 재생을 요청합니다. 같은 브라우저에서 선택을 유지하고 MY와 피드가 같은 상태를 사용합니다. 앱이 숨겨지거나 다른 화면으로 이동하면 일시정지합니다. 재생 거부, 미설정 자산, 재생 실패는 음소거로 표시하며 피드 이용을 막지 않습니다.
