# 출시 운영값과 인수 기준

- 상태: 초안. 전달 자료의 필수 운영값·QA 기준을 기록했으며 실제 값의 준비, 승인, 검증은 확인하지 않았습니다.
- 갱신일: 2026-10-21
- 근거: `0. 정책/05. QA : 인수 기준과 증빙.pdf`(`00-E`), `06. 운영 설정 : 출시 전 필수 입력.pdf`(`00-F`), 화면 `09.01`, 구현 기준 v1 · 2026.10.20. [자료 목록](../references/tomyx-2026-10-20/README.md), [정책 추출본](../references/tomyx-2026-10-20/policies.md)
- 관련 문서: [자료와 제품 범위](../specs/product-overview.md), [서비스 정책](service-rules.md), [공통 계약](../specs/service-contracts.md), [빌드와 배포](../specs/build-deploy.md), [디자인 기준](../specs/design-system.md)

## 목적과 적용 범위

기획 자료의 예시값을 운영값으로 오인하지 않고, 실제 서비스가 준비됐는지 확인할 기준을 관리합니다. 자료에 없는 주소·키·약관 승인 사실·자산 사용 권한은 임의로 채우지 않습니다. mock과 개발 화면 검수는 진행할 수 있지만 이를 실제 연동이나 공개 출시 검증으로 보고하지 않습니다.

`00-D`와 `00-F`는 필수값 누락 시 공개 운영 배포를 막도록 요구합니다. 현재 저장소에 이 제품 설정 검증이 자동 구현됐다는 뜻은 아닙니다. 기존 웹 자동 배포나 앱 내부 테스트 자동화와 연결할 방식은 별도로 구현·검증해야 합니다.

## 00-F · 운영 설정 원본

| ID | 필요한 값·자산 | 미설정·실패 시 동작 | 출시 조건 |
| --- | --- | --- | --- |
| LEGAL | `terms.body`, `terms.version`, `terms.effectiveAt`, `privacy.body`, `privacy.version`, `privacy.effectiveAt` | 약관 조회 오류, 동의 제출 차단 | 승인된 실제 게시본 필요. `0000년`, 예시 본문, 빈 문서 금지. 누락 시 공개 배포 차단 |
| AUTH | Apple/Google/Kakao의 `clientId`, 서버 비밀값, 허용 callback/redirect 주소, 운영 도메인 | 개발 환경의 미설정 공급자는 비활성·설정 안내 | 운영 3종 지원 중 하나라도 빠지면 배포 차단. 서버 검증 후 인증 성공. 비밀값은 클라이언트에 포함 금지 |
| CONTACT | 실제 수신 가능한 `supportEmail`, 빌드에서 주입하는 `buildVersion` | 주소가 없으면 문의 행 비활성·환경 오류 기록. 메일 앱이 없으면 주소 복사 | 문의 주소 누락 시 배포 차단. 샘플 `1.0.0`으로 버전 고정 금지 |
| ASSET | Pretendard·MaruBuri 서체 파일, 사용 가능한 배경·이미지·공급자 로고의 목록 | 소셜 버튼의 점선 네모를 실제 로고로 교체. 미확보 서체는 디자인 일치 미완료로 기록 | 서체·배경을 임의 변경하지 않음. 자료만으로 자산 사용 권한이나 실제 파일 확보를 확정하지 않음 |
| PUSH | 지원 여부, 서비스 워커, 공개 키, 발송 서버, 구독 저장 준비 | 미지원·미설정은 OFF·비활성. 핵심 읽기·쓰기 유지 | 웹의 선택 기능. 홈 화면 추가·권한·서버 구독 저장 성공을 모두 확인한 경우만 ON. 네이티브 대응은 미정 |
| CONTENT | 공개 도메인, 기본 배경, 선택 음원, 초기 콘텐츠 | 지역·헤어진 기간이 없으면 해당 행 숨김. 음원 미설정은 음소거. 초기 글 0건은 `04.03` | 예시 글과 실사용자 글 구분. 메타데이터를 채우려고 위치 수집 추가 금지 |

탈퇴의 보존·파기 안내는 실제 게시하는 개인정보 문서와 일치시킵니다. 공급자 키나 다른 비밀값을 이 Markdown에 기록하지 않습니다. 운영값이 준비되면 값의 저장 위치·확인 담당·검증 결과를 남기되 비밀값 자체는 제외합니다.

문의 메일에는 받는 주소와 앱 버전만 기본 제공하고, 글 본문·계정 ID는 자동 첨부하지 않습니다(`09.01-E3`). Push는 켜기 탭에서만 권한을 요청하며 앱 진입만으로 요청하지 않습니다. 끄기도 구독 해제와 서버 반영 성공 후 적용합니다(`09.01-E1`).

## 샘플과 실제 데이터 구분

디자인 속 인물·게시글·지역·기간·`9:41`·카카오 계정·`1.0.0`은 샘플입니다. 서버·기기·빌드값으로 교체하며, 개인 정보를 추론하거나 자동 수집하지 않습니다. 출시용 이미지·음원·폰트 파일과 사용 가능 여부는 자산 목록에서 추적합니다.

## 00-E · QA와 증빙

화면 번호와 원문의 AC 번호, 기기·뷰포트, 로그인 계정 종류, 초기 데이터, 실행 동작, 실제 결과, `requestId`, 캡처를 기록합니다. 다음 표는 실행할 기준입니다. 현재 모든 제품 기능 QA는 미실행입니다.

| 원문 QA ID | 검수 범위와 판정 기준 |
| --- | --- |
| QA-01–03 | 3개 에피소드의 A/B 분기, 장면 순서·빈 본문·진행 복원·이탈·공유 직접 진입. 실제 외부 앱 검색이나 메시지 발송 없음. 비로그인 쓰기 `08.02`, 로그인 후 초안 유무 분기 |
| QA-04–06 | 0자·공백·개행만 입력은 무효. `999/1,000/1,001`자, 이모지·한글 조합 확인. 요약 `19/20/21`자와 줄바꿈 검증. 편집·미리보기·이탈·복귀의 본문·커서 유지. 저장 실패·브라우저 재시작·계정 변경·초안 초기화 확인/취소 |
| QA-07–09 | 연타·느린 응답·`15초` 무응답·성공 응답 유실·종료 후 재시도에도 등록은 한 건. 실제 성공·`postId` 수신 전 완료 표시·초안 삭제 금지. 결과 확인 후 수정 허용. 완료 화면과 피드·내 글의 ID 일치 |
| QA-10–12 | Apple→Google→카카오 순서, 중복 요청 잠금. 공급자 취소·오류·늦은 콜백 구분. 동의는 모두 미선택으로 시작하고 필수 하나라도 빠지면 비활성. 문서 보기 후 체크 유지. 취소·동의 저장 실패 시 보호 API 실행 금지 |
| QA-13–15 | 공감 로그인 후 원래 목표 상태 1회 적용. 신고는 사유 선택, 차단은 확인으로 복귀. 다른 글·삭제 대상·세션 만료·다른 계정에서 대상/캐시 혼용 금지. 비로그인 안내와 데이터 0건·실패 구분 |
| QA-16–18 | 아래 `80px`/위 `8px`·최상단의 컨트롤 전환, + 위치·크기 유지. `20개` 커서·중복 ID 제거·추가 조회 실패의 기존 목록 보존. 탭·시트 복귀 스크롤 유지. 재생 거부·음원 미설정에서 읽기 가능 |
| QA-19–21 | 실제 복사 성공만 `07.02`, 실패는 수동 복사. 신고 미선택·중복·실패의 사유 보존. 숨김·차단 실패/취소는 목록 유지, 성공만 제외. 공개 중단·차단 상세 `07.09`와 일시 오류 구분 |
| QA-22–24 | 설정의 로그인 제한, 실제 계정·빌드값. 홈 화면 미추가·Push 미지원·권한 거절·구독 저장 실패 시 ON 금지. 문서 진입별 뒤로·동의 체크 유지. 문의 주소 없음·메일 앱 없음 분기 |
| QA-25–27 | 초안 있는 로그아웃의 삭제 안내·확인, 취소 시 보존. 서버 글 보존·개인 캐시 정리. 탈퇴 체크 전 비활성·실패 시 계정 유지·응답 유실의 같은 시도 조회. 완료 후 옛 공유 링크 열람 불가·뒤로 개인 화면 복원 금지 |
| QA-28–30 | 좁은 화면·큰 글자·키보드·safe area·스크린리더에서 본문·CTA 접근. 59개 UI의 레이어·이미지·컴포넌트 대조. 필수 운영값 누락 배포 차단. 예시 약관·점선 로고·샘플 계정값 운영 노출 금지 |

QA 표의 스크롤 경계는 요약된 원문 표기입니다. 실제 조건은 `00-A / SCROLL`의 아래 `80 CSS px 초과`, 위 `8px 이상` 또는 최상단이며 [디자인 기준](../specs/design-system.md)과 [피드 스펙](../specs/story-feed.md)을 함께 확인합니다.

## 출시 전 남은 확인

| 항목 | 현재 상태 | 확인할 담당 |
