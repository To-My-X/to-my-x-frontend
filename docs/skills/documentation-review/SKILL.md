# 문서 동기화 리뷰

저장소 루트를 기준으로 경로를 해석합니다. `docs/harness/documentation-sync.md`의 변경 유형별 기준에 따라 실제 변경과 문서를 대조합니다. 문서가 수정됐다는 사실만으로 통과시키지 않습니다.

## 실행 시점과 범위

- 커밋: 매 커밋 직전에 실행합니다. `git diff --cached`를 기준으로 실제 커밋될 내용을 검토하고, 작업 트리의 미반영 문서도 확인합니다. 여러 커밋으로 나누면 각 커밋이 코드와 문서의 일관성을 유지해야 합니다.
- 빌드: 웹 export, 로컬 네이티브 빌드, EAS 빌드를 시작하기 전에 실행합니다. HEAD와 staged·unstaged·untracked 변경을 포함해 실제 빌드에 들어갈 상태를 확인합니다. 원격 ref를 빌드한다면 해당 ref의 문서를 확인합니다.
- 단순 개발 서버 실행, lint, 타입 검사는 빌드 트리거가 아닙니다. 빌드 방법만 설명하는 질문도 실행 트리거에서 제외합니다.
- 직전 리뷰 이후 변경이 없다면 이전 결과와 현재 상태가 같은지 확인해 재사용할 수 있습니다. 파일이나 빌드 대상이 바뀌었다면 영향 범위를 다시 검토합니다.

## 검토 방법

1. `git status --short --branch`, `git diff`, `git diff --cached`, `git ls-files --others --exclude-standard`로 변경 범위를 파악합니다. 새 파일과 삭제·이동된 파일도 읽습니다. 빌드 대상에 미커밋 변경이 없다면 대상 코드·설정과 관련 문서를 대조합니다.
2. 변경 목적별로 관련 문서를 찾습니다. 서비스 규칙과 판단 근거는 `docs/policy/`, PRD·IA·Tech Spec과 완료 조건은 `docs/specs/`, 운영 절차는 `docs/harness/`, 협업 규칙은 `docs/conventions/`에서 확인합니다. 실행·빌드 설정은 README, package.json, eas.json 등 실제 파일과 비교합니다.
3. 누락된 요구사항, 오래된 설명, 코드와 정책의 충돌, 미검증 결과를 검증 완료로 적은 부분, 끊어진 문서 링크를 찾습니다. 정책과 스펙에 같은 규칙을 중복 정의하지 않습니다.
4. 확인된 사실에 따른 문서 누락은 현재 요청 범위 안에서 수정합니다. 구현에 맞추려고 확정 정책을 바꾸거나 알 수 없는 기획 의도를 만들어내지 않습니다. 의사결정이 필요한 충돌은 구체적으로 보고합니다.
5. 커밋이라면 문서 수정이 해당 커밋에 포함되는지 staged 내용을 다시 확인합니다. 다른 작업자의 변경이나 별도 목적의 파일은 임의로 stage하지 않습니다. 빌드라면 필요한 문서가 업로드 대상에서 제외되지 않는지도 확인합니다.

## 결과와 후속 작업

- `통과`: 변경과 문서가 일치합니다. 문서 수정이 불필요하면 이유를 짧게 밝힙니다.
- `보완 완료`: 누락을 수정하고 실제 커밋·빌드 대상을 다시 확인했습니다.
- `보류`: 정책 충돌이나 확인할 수 없는 대상 때문에 판단할 수 없습니다. 미해결 항목과 필요한 결정을 보고하며 커밋·빌드를 진행하지 않습니다.

실행 전 보고에는 대상, 확인한 문서, 수정 내용 또는 수정 불필요 이유, 남은 문제를 짧게 남깁니다. 새 정책·결정은 해당 원본에, 후속 작업과 검증 상태는 `docs/harness/handoff.md`에 기록합니다. 매 실행마다 의미 없는 날짜 변경이나 별도 리뷰 파일을 만들지 않습니다.

문서 리뷰 통과는 테스트·빌드 성공이나 배포 승인을 뜻하지 않습니다. 커밋·빌드가 끝나면 실제 결과와 미실행 항목을 보고하고 필요한 인수인계를 갱신합니다. 결과 기록만으로 빌드를 다시 실행하는 순환을 만들지 않습니다. 이 스킬을 호출했다는 이유로 커밋·푸시·배포 권한이 추가되지는 않습니다.
