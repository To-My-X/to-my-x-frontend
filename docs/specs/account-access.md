# 로그인·동의·설정·계정 종료

## 문서 정보

- 유형: 화면·기능·사용자 흐름
- 명세 상태: 초안. 전달 자료의 동작을 반영했으며 실제 인증·세션·네이티브 연동 방식은 미정입니다.
- 구현 상태: 화면 연결 골격 구현(mock 로그인·동의·설정·로그아웃·탈퇴). 실제 공급자·운영 동의·서버 연동은 미착수
- 검증 상태: 일부 확인. 자료 대조 완료, 기능 검증 미실행
- 갱신일: 2026-10-21
- 입력 자료: Desktop `ToMyX/1. 개발명세`의 08.01–08.07, 09.01–09.06, `2. 디자인 가이드`의 08–09, `0. 정책`의 00–06. 개발명세는 `구현 기준 v1 · 2026.10.20`입니다. 파일별 출처는 [제품 명세 개요](product-overview.md)에서 관리합니다.
- 적용 근거: 자료가 명시한 UI·실행 조건·예외·복귀를 기준으로 정리했습니다. 자료 안의 출시 1차 기본값과 과거 합의·실제 구현 완료를 구분합니다.
- 관련 정책: [서비스 규칙](../policy/service-rules.md), [운영·출시 조건](../policy/launch-operations.md)
- 관련 스펙: [서비스 계약](service-contracts.md), [스토리 피드](story-feed.md), [디자인 시스템](design-system.md), [프론트엔드 아키텍처](frontend-architecture.md)

## 1. 목적과 범위 — PRD

사용자는 로그인 없이 이야기를 둘러보고, 작성·공감·신고·차단·개인 화면을 이용할 때 인증합니다. 인증 뒤에는 하려던 동작과 읽던 위치로 돌아갑니다. 설정에서는 계정·알림·문서를 확인하고 로그아웃 또는 탈퇴할 수 있습니다.

범위는 로그인·동의·게스트 MY 7개, 설정·로그아웃·탈퇴 6개의 UI 상태입니다. 공급자 계정 자동 병합, 별도 프로필 설정, 생년월일 수집, 추가 약관 선택 항목은 포함하지 않습니다. 실제 약관 작성·법적 보관 기간 결정은 이 프론트엔드 스펙의 범위가 아닙니다.

## 2. 정보 구조와 흐름 — IA

### 로그인 진입과 복귀

| 진입 동작 | 로그인 진입점 | 인증·동의 완료 후 |
| --- | --- | --- |
| 새로 글쓰기 진입 | 08.02 글쓰기 시트 | 현재 계정 초안 있음 03.09, 없음 03.01. 기존 본문·대상은 보존하고 자동 공개하지 않는다. |
| 편집·공개 확인 중 세션 만료 | 08.02 글쓰기 시트 | 입력과 작성 단계를 보존한다. 특히 공개 확인 `03.04`에서 만료되면 재인증 후 `03.04`로 복귀해 다시 승인받는다(`03.04-E1`). 자동 제출하지 않는다. |
| 공감 | 08.03 공감 시트 | 원래 postId를 재조회하고 원래 `desiredReaction`을 한 번 적용 |
| 신고 | 08.03을 신고 안내 문구로 재사용 | 07.06에서 사유 선택 또는 보존한 사유 확인. 자동 접수하지 않는다. |
| 작성자 차단 | 08.03을 차단 안내 문구로 재사용 | 07.08에서 확인. 자동 차단하지 않는다. |
| MY | 08.07 → 08.01 | 현재 계정 내 글 재조회 후 06.01/06.02 |
| 알림 | 05.03 → 08.01 | 현재 계정 알림 재조회 후 05.01/05.02 |
| 설정 직접 접근·설정에서 세션 만료 | 08.01 | 설정 복귀 의도를 유지하고 09.01 재조회 |
| 직접 로그인 | 08.01 | 유효한 복귀 의도가 없으면 피드 04.01 |

복귀 정보는 `originRoute`, `postId`, `authorId`, `action`, `desiredReaction`, `scroll`, `draftKey`로 표현합니다. 필요한 값만 보관하고 한 번 사용하거나 닫기·취소 시 정리합니다. 로그인 뒤 공개 상태·대상·세션을 재검증하며, 다른 계정으로 인증되면 이전 계정의 초안·MY·알림을 넘기지 않습니다.

### 로그인 08.01–08.05

| 화면 | 구성·동작 | 성공·실패·취소 |
| --- | --- | --- |
| 08.01 로그인 시작 | 전체 화면. Apple → Google → 카카오 버튼, `먼저 둘러볼게요` | 선택한 공급자와 복귀 의도를 저장하고 08.04. 뒤로·둘러보기는 진입 화면/위치, 이력이 없으면 04.01 |
| 08.02 글쓰기 시트 | 기존 화면 위 시트. 글쓰기 안내와 동일 공급자 버튼, `나중에 할게요` | 배경 터치·보조 읽기를 막고 원래 스크롤 보존. 바깥 탭·뒤로·나중에는 보류 동작 없이 원래 화면 |
| 08.03 공감 시트 | 공감·신고·차단 의도에 맞춰 안내 문구 변경 | 로그인 성공만으로 신고·차단을 실행하지 않는다. 취소는 원래 글·위치 |

| 08.05 실패 | 짧은 오류 안내, `다시 시도하기`, `먼저 둘러볼게요` | 재시도는 같은 공급자로 새 attemptId, 복귀 의도 유지. 둘러보기·뒤로는 원래 피드/05.03/08.07 |

공급자 창의 사용자 취소는 실패 화면으로 강제 이동하지 않고 원래 로그인 화면·시트에서 취소 안내를 표시합니다. 08.04의 취소는 시도를 무효화하며 늦게 도착한 콜백이 세션이나 동작을 다시 적용하지 못하게 합니다. URL이나 클라이언트 상태만으로 로그인 성공을 판정하지 않습니다.

### 동의 08.06과 게스트 MY 08.07

08.06은 최초 로그인 또는 현재 필수 문서 버전에 미동의일 때 표시합니다. 이용약관·개인정보 처리방침·만 14세 이상 세 항목과 `모두 동의하기`는 최초 미선택입니다. 전체 체크는 모두 선택/해제하고, 개별 항목을 해제하면 전체 체크도 해제합니다.

문서 보기에서 09.02/09.03으로 이동해도 체크와 복귀 의도를 보존합니다. 유효한 문서 버전이 있고 필수 세 항목을 모두 선택해야 `동의하고 시작하기`를 활성화합니다. 서버 저장 실패는 체크를 유지하고 오류·재시도를 표시합니다. 뒤로 또는 미동의 종료는 임시 세션과 보류 의도를 정리하고 원래 둘러보기 화면으로 돌아갑니다. 만 14세 이상은 체크 확인이며 추가 생년월일 입력을 만들지 않습니다.

08.07에는 로그인 안내, 스토리/MY 탭, 소리, `+`가 있습니다. 설정 아이콘·내 글 목록은 표시하지 않고 개인 데이터 API도 호출하지 않습니다. 로그인하기는 08.01, `+`는 08.02, 스토리 탭은 기존 피드 위치로 연결합니다.

### 설정·문서 09.01–09.03

09.01은 로그인 후 MY 설정 아이콘에서 진입합니다. 계정, 알림, 안내, 계정 관리 순으로 구성하고 하위 화면의 뒤로는 실제 진입 경로를 따릅니다.

| 항목 | 표시·동작 | 실패·복귀 |
| --- | --- | --- |
| 계정·버전 | 실제 로그인 공급자·상태와 배포 빌드 버전 | 샘플 `카카오 계정`, `1.0.0`을 고정하지 않는다. |
| 푸시 알림 | 자료상 홈 화면 추가 + Push 지원 + 서버 준비 상태에서 OFF→ON 탭으로 권한 요청. 구독·서버 저장 성공 후 ON | 미지원·미설정은 OFF·비활성. 권한 거부는 기기 설정 안내. 진입만으로 권한을 요청하지 않는다. |
| 푸시 끄기 | 구독 해제와 서버 반영 성공 후 OFF | 해제 실패·부분 성공의 표시와 재시도 계약은 구현 전 보완 |
| 이용약관·개인정보 | 각각 09.02/09.03. 문서 종류·버전·시행일·전체 본문을 조회해 세로 스크롤 | 없거나 조회 실패면 `문서를 불러올 수 없어요.`와 재시도. 빈 문서·동의 완료로 처리하지 않는다. |
| 문의하기 | `supportEmail`로 메일 앱 열기. 받는 주소와 앱 버전만 기본 제공 | 메일 앱이 없으면 주소 복사. 주소 미설정이면 행 비활성·환경 오류 기록 |
| 로그아웃 | 09.04 확인 시트 | 취소는 설정 유지 |
| 탈퇴하기 | 09.05 안내 | 요청 전 계속 사용하기·뒤로는 설정 유지 |

설정 진입 시 현재 브라우저 권한과 서버 구독을 다시 확인합니다. 문의에 본문·계정 ID를 자동 첨부하지 않습니다. 문서를 08.06에서 열었다면 해당 체크 상태로, 설정에서 열었다면 09.01로 복귀합니다. 문서 재시도는 같은 종류·버전을 조회합니다.

로그아웃은 서버 게시글을 보존합니다. 탈퇴는 정책의 삭제 범위를 적용하며, 화면만 비우고 완료로 처리하지 않습니다. 탈퇴 성공 후 과거 공유 링크는 열람 불가로 바뀌고 남은 목록·공감 수도 갱신합니다. 세션·초안·개인 캐시·푸시 연결·진행 상태·저장된 선택을 정리하며, 새 로그인에서 삭제 전 데이터를 자동 복구하지 않습니다.

## 3. 구현 설계 — Tech Spec

### 책임과 상태 소유

배치는 구현 제안입니다. `src/features/auth/`는 로그인·동의와 인증 시도 상태, `src/features/settings/`는 설정·문서 보기·계정 종료를 맡습니다. 라우트와 보호 기능의 연결은 `src/app/`에서 조합합니다. 공급자 버튼·체크·시트 등 공통 UI는 [디자인 시스템](design-system.md)에 맞춰 재사용하며 기능 간 직접 import를 만들지 않습니다.

| 상태 | 소유·수명 제안 | 정리 조건 |
| --- | --- | --- |
| 검증된 세션·동의 완료 여부 | 서버가 원본. 앱 상위 인증 상태는 확인된 결과만 반영 | 로그아웃·탈퇴·만료·계정 변경 |
| 로그인 시도·공급자 | 인증 흐름이 attemptId별로 소유 | 완료·취소·재시도 시 이전 콜백 무효화 |
| returnIntent | 보호 액션을 시작한 상위 흐름에서 1회성으로 보관 | 사용·닫기·취소 후 정리. 개인 입력은 URL에 노출하지 않는다. |
| 동의 체크·문서 버전 | 동의 화면 흐름이 소유 | 문서 열람 동안 보존, 종료 후 정리 |
| 설정·권한·구독 | 서버 계정 정보와 플랫폼 권한이 원본. 화면 진입 때 재조회 | 계정 변경·로그아웃·탈퇴 |
| 탈퇴 operationId·처리 상태 | 결과 확인까지 유지. 재실행·앱 복귀에도 같은 시도 조회 | 서버의 확정 결과 확인 후 정리 |

세션 저장 매체, 웹 redirect 사이의 의도 복구, operationId 영속화, 네이티브 인증 어댑터는 아직 선택하지 않았습니다. 토큰·비밀키를 UI나 로그에 출력하지 않습니다. `returnIntent`가 가리키는 계정·대상 권한을 서버 검증 없이 신뢰하지 않습니다.

### 데이터·오류·외부 연동

논리 연산은 `startLogin`, `completeLogin`, `cancelLogin`, `getConsentDocuments`, `acceptConsent`, `getAccountSettings`, `subscribePush`, `unsubscribePush`, `logout`, `deleteAccount`, `getDeletionStatus`입니다. 세부 필드와 공통 오류는 [서비스 계약](service-contracts.md)에 둡니다. 실제 REST 경로·SDK·인증 서버·세션 방식은 미정입니다.

- `APPLE`, `GOOGLE`, `KAKAO`를 화면 순서와 연결합니다. 공급자 설정이 없는 개발 환경은 해당 버튼을 비활성화하고 설정 안내를 표시합니다. 운영 지원 조건은 운영 정책의 출시 점검을 따릅니다.
- 서버가 공급자 결과를 검증하고 세션을 발급한 뒤에만 인증 성공으로 전환합니다. 동의 필요 상태에서는 보호 API와 보류 동작을 실행하지 않습니다.
- 동의 문서의 종류·버전·시행일·본문을 함께 확인합니다. 서버가 사용자·문서 버전·동의 시각을 기록하고 성공한 뒤 복귀합니다.
- 같은 공급자 재시도에는 새 attemptId를 사용하지만, 이미 진행 중인 인증 시도를 중복 실행하지 않습니다. 사용자 취소·네트워크 오류·공급자 실패는 서로 구분합니다.
- 로그아웃은 서버 종료 성공 후 로컬 개인 데이터를 정리합니다. 오프라인 상태를 성공으로 표시하지 않습니다. 종료된 보호 화면을 복원하지 않도록 내비게이션 이력을 교체합니다.
- 탈퇴는 동일 operationId로 중복 생성을 막고 결과를 조회합니다. 응답이 없다는 이유만으로 성공·실패·복구·재가입 가능을 단정하지 않습니다.
- 실제 약관·개인정보 문서, 문의 주소, 공급자 callback/redirect, Push 설정은 [운영·출시 조건](../policy/launch-operations.md)에 따라 준비합니다. 개발용 문구를 운영 문서로 사용하지 않습니다.

## 카카오 로그인 실연동 — 2026-10-28

서버 `https://api-tomyx.rhkr8521.com`(/api/v1/auth)와 카카오 웹 로그인을 연동했습니다.

- 웹(08.01~03): 카카오 인가 코드 플로우. `scope=openid` 포함 인가 요청 → `/login` 콜백의 `code`를 `POST /api/v1/auth/login/kakao/code`로 교환합니다. state는 난수+복귀 키로 만들어 sessionStorage 보관값과 대조하고, 불일치는 실패(08.05)로 처리합니다. 성공 응답의 `newMember` 또는 이 기기의 동의 기록 부재 시 08.06 동의로 보냅니다.
- 세션: access 토큰은 메모리, refresh 토큰·memberId·동의 여부는 `tomyx.auth.v1`(웹 localStorage, 네이티브는 세션 메모리)에 보존합니다. 앱 시작 시 refresh 회전(`POST /token/refresh`)으로 복원하고 실패하면 게스트로 시작합니다. 사용한 refresh 토큰은 재사용되지 않으므로 회전 결과를 항상 저장합니다.
- 로그아웃(09.04)·동의 전 이탈: `POST /logout`으로 토큰 계열을 폐기(실패해도 로컬 정리 유지)하고 게스트로 돌아갑니다.
- 08.04 진행 중·08.05 실패 상태를 로그인 시트에 구현했습니다. Apple·Google은 공급자 설정 전 비활성입니다.
