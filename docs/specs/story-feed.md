# 스토리 피드·MY·알림·이야기 관리

## 문서 정보

- 유형: 화면·기능·사용자 흐름
- 명세 상태: 초안. 전달 자료의 화면·행동 기준을 옮겼으며, 구현 배치 제안과 미결정 사항은 별도로 표시합니다.
- 구현 상태: 04.01~04.04 mock 피드 구현 완료. 나머지 기능과 실제 API 연동은 미착수.
- 검증 상태: 일부 확인. 자료 대조와 이번 mock 피드의 Chromium 모바일 웹 검증 완료. 네이티브·실제 API는 미검증
- 갱신일: 2026-10-21
- 입력 자료: Desktop `ToMyX/1. 개발명세`의 04.01–07.09, `2. 디자인 가이드`의 04–07, `0. 정책`의 00–06. 개발명세는 `구현 기준 v1 · 2026.10.20`입니다. 파일명과 출처는 [제품 명세 개요](product-overview.md)에서 관리합니다.
- 적용 근거: 전달 자료의 구체적인 화면 동작을 우선합니다. 자료에 적힌 출시 1차 기본값을 과거 합의나 구현 완료로 해석하지 않습니다.
- 관련 정책: [서비스 규칙](../policy/service-rules.md), [운영·출시 조건](../policy/launch-operations.md)
- 관련 스펙: [서비스 계약](service-contracts.md), [로그인·계정](account-access.md), [디자인 시스템](design-system.md), [프론트엔드 아키텍처](frontend-architecture.md)

## 1. 목적과 범위 — PRD

### 이번 구현 범위 — 2026-10-21

사용자가 메인 피드의 정상·스크롤·로딩·빈 상태·오류를 모바일 웹에서 확인하도록 요청했습니다. 이번에는 `04.01`~`04.04`와 추가 페이지 조회·실패 재시도만 구현합니다. 루트 `/`에서 피드에 바로 진입하며, 첫 방문 시뮬레이션 연결은 후속 작업입니다.

- 본문·요약·배경·선택 메타데이터, 헤더·하단 컨트롤을 표시합니다. 제목은 mock 본문에 대응하는 fixture로 제공하며 입력·요약 계산 기능은 이번 범위 밖입니다.
- 20개씩 최대 60개의 fixture를 읽습니다. 이는 검수 데이터 크기이며 서비스의 글 수 제한이 아닙니다. 최초/추가 로딩, 0건, 최초 오류, 추가 조회 오류를 분리합니다. 실패 시 재시도로 복구합니다.
- 아래 방향 누적 80px 초과에서 벨·소리·탭을 숨기고, 위 방향 누적 8px 이상 또는 최상단에서 복원합니다. 방향이 바뀌면 기준점을 다시 잡으며 +의 위치·크기는 유지합니다. 웹에서 실제 CSS px로 검증하고 네이티브는 추후 검증합니다.
- 공감·공유·더보기·알림·MY·쓰기는 시각 요소와 비활성 접근성 상태까지만 제공합니다. 인증이나 쓰기 완료를 흉내 내지 않습니다. 04.04의 +는 참고 UI대로 표시하되 동작 확정 전 비활성입니다. 음원이 없어 소리 컨트롤도 음소거·비활성으로 표시합니다.
- 개발 전용 `/feed-preview`에서 정상·지속 로딩·빈 상태·초기 실패·추가 조회 실패·긴 글 시나리오로 이동합니다. 루트의 `scenario` 매개변수는 개발 환경에서만 적용하며 릴리스에서는 무시합니다. 제품 화면에는 검수 패널을 넣지 않습니다.
- 원본 PDF에 포함된 배경 이미지는 추출해 mock 검수용으로만 사용합니다. 실제 자산 사용 확인은 공개 출시 전에 필요합니다. 정확한 토큰 값·넓은 화면 기준은 임시값으로 [디자인 시스템](design-system.md)에 기록합니다.

구현은 `src/features/feed/`의 화면·hook·mock API·스크롤 계산으로 나누고, 공통 UI는 아이콘 버튼·텍스트 버튼만 만듭니다. React Native `FlatList`로 렌더 범위를 제한하며 현재 목록 상태는 feature hook에서 관리합니다. 라우트가 시나리오를 해석해 전달하고, 화면에서 HTTP 요청을 직접 실행하지 않습니다.

| 이번 완료 조건 | 검증 방법 | 현재 결과 |
| --- | --- | --- |
| 정상 피드의 배경·본문·컨트롤이 375×812 모바일 뷰포트에 표시됨 | 브라우저 캡처·원문 비교 | 통과 |
| 로딩 동안 빈 상태가 보이지 않고, 빈 상태와 초기 오류가 구분됨 | 개발 시나리오별 확인 | 통과 |
| 초기 오류 재시도 후 정상 목록 표시, 추가 조회 실패는 기존 목록 유지 | 클릭·목록 개수·스크롤 확인 | 통과 |
| 80px/8px 경계와 + 위치 고정, 숨긴 요소가 포커스에서 제외됨 | 스크롤 계산 테스트·브라우저 확인 | 통과 |
| 추가 조회 연타와 화면 이탈에서 중복 페이지·늦은 상태 변경 없음 | mock API 취소 테스트·브라우저 페이지 복구 확인 | 통과 (요청 중복은 in-flight 잠금 코드 대조) |
| 좁은/넓은 화면·긴 글·확대에서 본문 접근 가능 | 320/375/430/데스크톱 및 글자 확대 확인 | 통과 |
| lint·타입 검사·웹 export 통과 | 프로젝트 명령 실행 | 통과 |

방문자는 로그인 없이 공개된 이야기를 읽고 공유합니다. 로그인한 사용자는 공감과 신고·차단을 이용하고, MY와 알림에서 자신이 남긴 이야기를 다시 찾습니다. 익명은 공개 표시 방식이며, 실제 소유권과 개인 설정은 계정으로 구분합니다.

이 스펙은 피드 4개, 알림 3개, MY 3개, 공유·관리 9개의 UI 상태를 다룹니다. 각 번호는 디자인 상태의 식별자이며, 별도 URL을 19개 만들라는 뜻이 아닙니다. 로그인과 글쓰기 연결은 담당 스펙에 위임합니다. 댓글·검색·사용자 프로필·공개 후 개별 수정/삭제·숨김/차단 해제 UI는 출시 1차 범위에서 제외합니다.

## 2. 정보 구조와 흐름 — IA

### 피드 04.01–04.04

일반 진입, 시뮬레이션 이탈, 등록 완료의 피드 이동, 스토리 탭에서 진입합니다. 첫 방문의 시뮬레이션 배정은 별도 진입 흐름을 따르고, 공유 링크가 있으면 대상 글을 먼저 표시합니다.

| 화면·상태 | 구성과 동작 | 다음 상태·복구 |
| --- | --- | --- |
| 최초 로딩 | 콘텐츠 영역 로딩. 0건 안내를 먼저 띄우지 않는다. | 성공 시 04.01 또는 04.03, 최초 조회 실패 시 04.04 |
| 04.01 메인 / 스토리 | 공개 이야기의 배경·요약·본문, 공감·공유·더보기, 헤더 벨, 소리, 스토리/MY, `+` | 공감은 대상 상태 변경, 공유는 07.01, 다른 사람 글의 더보기는 07.03 |
| 04.02 메인 / 스크롤 후 | 아래로 80 CSS px를 초과해 이동하면 벨·소리·탭을 숨기고 `+`만 유지한다. 본문과 이미지가 스크롤된다. | 위로 8px 이상 이동하거나 최상단이면 04.01 컨트롤 복원 |
| 04.03 메인 / 이야기 없음 | 표시 가능한 글이 없다는 안내. `+`, 벨, 스토리/MY, 소리 동작 유지 | `+`는 로그인·초안 분기, 벨/MY는 각각 권한 분기 |
| 04.04 메인 / 불러오기 실패 | 최초 조회 실패 안내와 `다시 불러오기`, 벨·탭·소리 | 같은 조건으로 재조회. 기존 목록이 있으면 전체 오류 화면 대신 목록 말미에 오류 표시 |
| 추가 조회 중·실패 | 기존 목록·읽던 위치를 유지하고 말미에 진행 또는 재시도 표시 | 같은 조회 조건으로 재시도. 실패를 목록 0건으로 바꾸지 않는다. |

`+`의 좌표·크기는 04.01/04.02에서 같습니다. 숨긴 컨트롤은 터치와 접근성 탐색에서도 제외합니다. 04.02 디자인에는 명세상 숨겨야 할 벨·소리 아이콘이 남아 있어 [디자인 시스템](design-system.md)에서 차이를 추적합니다. 04.04에는 시각적으로 `+`가 있지만 동작 표에 쓰기 이벤트가 없어 목적지를 확인해야 합니다.

피드 액션의 목적지는 다음과 같습니다.

| 동작 | 조건·목적지 | 취소·실패·복귀 |
| --- | --- | --- |
| 공감 | 공개 중인 다른 사람 글. 게스트는 08.03, 인증·동의 후 대상 재조회와 원래 목표 상태 1회 적용 | 기존 공감 상태·수를 유지하고 같은 목표 상태로 재시도. 원래 postId를 유지한다. |
| 공유 | 열람 가능한 공개 글이면 로그인 없이 07.01 | 주소 조회 실패는 시트 안 오류, 공개 중단은 07.09 |

| 벨 | 로그인 사용자는 알림 조회, 게스트는 05.03 | 복귀할 탭·대상·스크롤 보존 |
| MY | 로그인 사용자는 내 글 조회, 게스트는 08.07 | 스토리로 돌아오면 기존 피드 위치 복원 |
| 스토리 탭 | 다른 탭에서 돌아오면 기존 목록·위치 복원 | 현재 탭을 다시 눌러도 이동·재조회하지 않는다. |
| 소리 | 직접 탭으로 재생/음소거 요청 | 재생 거부·음원 없음·실패는 음소거 표시. 읽기를 막지 않는다. |

### 알림 05.01–05.03

알림 화면은 뒤로 버튼과 `알림` 헤더를 사용하며 하단 탭과 `+`가 없습니다. 게스트에게 개인 알림 API를 호출하지 않습니다.

| 화면·상태 | 표시·동작 | 다음 상태·복구 |
| --- | --- | --- |
| 05.03 로그인 전 | 로그인 안내와 `로그인하기` | 08.01에서 인증·동의 후 재조회. 취소하면 05.03으로 복귀 |
| 조회 중·실패 | 로딩 또는 오류·재시도 | 성공 전 05.01을 표시하지 않는다. |
| 05.01 빈 상태 | 로그인 계정 조회가 성공했고 0건인 경우 빈 안내 | 뒤로는 벨을 누른 화면의 탭·대상·위치 복원 |
| 05.02 목록 | 최신순 한 줄 메시지와 시간, 읽지 않은 항목 강조 | 항목의 읽음 저장 성공 후 벨 갱신. postId가 있으면 06.03, 환영 항목은 목록 유지 |

벨의 점은 서버의 `unreadCount > 0`일 때 표시합니다. 화면 진입만으로 모두 읽음 처리하지 않습니다. 읽음 저장 실패는 미읽음 상태를 유지하고 재시도를 안내합니다. 상세 조회가 열람 불가면 07.09, 일시 장애면 오류·재시도로 구분합니다.

06.03은 서버가 소유권을 검사합니다. 수정·개별 삭제·내 글 공감·내 글 신고 메뉴를 만들지 않습니다. 소리 설정은 피드와 MY가 공유합니다. 이력이 없는 직접 진입의 뒤로는 04.01이며, 세션 만료 시 이전 계정의 목록·상세·알림을 남기지 않습니다.

## 3. 구현 설계 — Tech Spec

### 책임과 상태 소유

아래 배치는 [아키텍처](frontend-architecture.md)를 적용한 제안이며 아직 파일을 만들지 않았습니다.

| 책임 | 배치 제안 | 소유 상태 |
| --- | --- | --- |
| 공개 피드·공개 상세·공감·공유·관리 | `src/features/feed/` | 피드 페이지·커서·조회 오류, 대상 글별 변경 요청, 열린 시트·신고 선택 |
| 내 이야기 목록·상세 | `src/features/my-posts/` | 계정별 서버 데이터와 MY 스크롤 위치 |
| 알림 | `src/features/notifications/` | 계정별 목록·미읽음 수·읽음 요청 |
| 라우팅·탭·기능 연결 | `src/app/`의 얇은 진입점 | 진입 경로, 선택 탭, 상세 ID, 복귀 정보 |
| 공통 시트·버튼·상태 UI | `src/components/` | 호출자가 전달한 표시 상태. HTTP 요청을 직접 실행하지 않는다. |

내 글 상세와 공개 상세는 표시 요소를 공유할 수 있지만 소유권 검사와 허용 액션은 구분합니다. 기능끼리 직접 import하지 않고 상위 라우트에서 콜백·데이터로 연결합니다. 여러 기능이 실제로 공유할 게시글 모델·오디오 상태의 소유 위치는 첫 구현에서 정하고 중복 원본을 만들지 않습니다.

서버 목록·공감 상태와 화면의 탭·시트·스크롤을 분리합니다. 진행 중 액션은 `postId`/`authorId`와 목표 상태를 요청 시작 시 고정합니다. 현재 화면에 보이는 다른 카드로 요청 대상을 바꾸지 않습니다. 스크롤 복원 정보는 화면 수명 동안 유지하고, 개인 데이터 캐시는 현재 계정으로 구분해 로그아웃·탈퇴·계정 변경 시 정리합니다.

### 데이터와 외부 연동

논리 연산은 `listFeed`, `listMyPosts`, `getPost`/내 글 소유권 검사, `setReaction`, `getShareLink`, `hidePost`, `reportPost`, `blockAuthor`, `listNotifications`, `markNotificationRead`입니다. 입력·응답과 공통 오류는 [서비스 계약](service-contracts.md)에 둡니다. REST 경로·백엔드·실제 연동은 미정이며, mock 검수와 서버 연동 완료를 구분합니다.

- 피드·MY는 원본 계약의 커서와 정렬을 사용합니다. 클라이언트는 같은 ID를 중복 표시하지 않고 추가 조회 실패 때 기존 목록을 보존합니다. 등록·숨김·차단 성공 후 관련 목록을 무효화합니다.
- 숨김 저장은 게스트의 로컬 저장과 로그인 사용자의 서버 저장을 구분합니다. 로그인 시 합집합 병합 정책은 존재하지만 병합 API·실패 복구 계약은 아직 없습니다.
- 변경 요청은 동일 액션의 중복 탭을 잠그고 실제 성공 후 상태를 반영합니다. 15초 응답 유실은 결과 불명으로 다루며, 확인 없이 새로운 작업 ID로 반복하지 않습니다. 개별 관리 연산의 상태 확인 계약은 추가 정의가 필요합니다.
- 공감은 단순 증가 API가 아닌 목표 상태 설정입니다. 성공 결과의 `reacted`·`reactionCount`를 사용하고 실패 시 기존 값을 유지합니다.
- 읽음 성공 후 알림과 벨의 미읽음 수를 함께 갱신합니다. 생성 중복 방지는 서버 책임입니다.
- 비공개·차단 글의 원문을 받은 뒤 UI만 숨기는 방식은 사용하지 않습니다. 서버가 권한과 공개 상태를 확인합니다.
- 공유 주소는 운영 공개 도메인에서 생성합니다. 계정·작성자·세션·추적 토큰을 붙이지 않습니다. 복사 실패 대체 동작은 플랫폼별 구현에서 제공합니다.

공통 레이아웃과 최소 터치 영역, 시트 배경 비활성·포커스 복원은 [디자인 시스템](design-system.md)을 따릅니다. 지역·헤어진 기간·인물·게시글은 예시이며, 값이 없으면 해당 메타데이터 행을 숨깁니다. 위치나 교제 정보를 추론·수집하지 않습니다.

소리는 기본 음소거이며 직접 탭에서만 재생을 요청합니다. 앱이 숨겨지거나 다른 화면으로 이동하면 일시정지합니다. 피드와 MY가 선택 상태를 공유하되 실제 재생 성공과 선호 설정을 혼동하지 않습니다. 음악·배경·폰트는 승인된 자산을 사용합니다.

무한 목록은 실제 이미지 크기·글 길이·누적 페이지 수를 늘려 스크롤 끊김, 메모리, 이미지 로딩, 위치 복원을 측정합니다. 리스트 라이브러리, 유지할 페이지 수, 프리로드 범위, FPS·메모리 합격 수치는 아직 정하지 않았습니다. 영상·광고 삽입·자동 재생·한 장씩 스냅하는 동작은 전달 자료에 구체 계약이 없어 별도 정의 전 구현 범위로 넣지 않습니다.
