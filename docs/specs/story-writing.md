## 1. 목적과 범위 — PRD

로그인한 사용자가 본문을 쓰고 공개 모습을 확인한 뒤 익명 이야기로 등록한다. 입력을 잃지 않고 이어 쓸 수 있어야 하며, 연결이 끊겨도 같은 글을 중복 등록하지 않아야 한다.

범위는 본문 편집, 입력 검증, 자동 요약, 미리보기·공개 확인, 초안 저장·복원·초기화, 등록·재시도·완료의 12개 화면 상태다. 제목·지역·기간·별도 피드 문장 입력, 초안 기기 간 동기화, 공개 후 개별 글 수정·삭제는 제외한다. 자동 요약은 원문의 앞부분을 발췌하는 규칙이며 AI 생성 기능으로 해석하지 않는다.

| ID | 요구사항·적용 조건 | 근거·정책 연결 | 상태 |
| --- | --- | --- | --- |
| WRITE-R01 | 로그인·필수 동의를 확인한 뒤 초안 유무에 따라 진입한다. 인증이 만료돼도 본문과 복귀 의도를 보존한다. | `0-01 AUTH/RETURN`, `0-03`, 서비스 규칙의 작성 권한 | 자료 기준 확정 |
| WRITE-R02 | 본문만 입력하고 공통 INPUT 규칙으로 유효성·카운터·입력 한도를 일치시킨다. | `0-01 INPUT`, `1-03.01/02/07/08 F1/F2`, 서비스 규칙의 본문 | 자료 기준 확정 |
| WRITE-R03 | 같은 SUMMARY 규칙으로 미리보기·피드·MY에 쓸 요약을 계산하며 본문을 변경하지 않는다. | `0-01 SUMMARY`, `1-03.03 F1/F2`, 서비스 규칙의 요약 | 자료 기준 확정 |

| WRITE-R05 | 미리보기와 확인 진입만으로 등록하지 않는다. 명시적 공개 승인 후 시도 ID를 보관하고 제출한다. | `1-03.03/04`, 서비스 계약의 등록 | 자료 기준 확정 |

정책 수치·삭제 조건은 서비스 규칙을 원본으로 관리한다. 아래 상태 전이와 검증 기준은 해당 정책을 작성 화면에 적용한 것이다.

## 2. 정보 구조와 흐름 — IA

### 진입과 화면 상태

시뮬레이션의 `이 마음 남기기`, 피드·MY의 쓰기 동작 등에서 진입한다. 비로그인은 `08.02`, 필수 동의 미완료는 동의 흐름을 거친다. 현재 계정의 초안이 없으면 `03.01`, 있으면 `03.09`다. 이전 등록의 결과가 미확정이면 새 편집을 시작하기 전에 기존 시도를 조회한다.

| 화면·원본 ID | 진입·표시 | 동작과 다음 상태 |
| --- | --- | --- |
| `03.01` / `1-03.01` | 신규 빈 본문, `0 / 1,000자`, 미리보기 비활성 | 입력 → `03.02` 또는 `03.08`. 빈 본문 닫기 → 진입 화면/`04.01` |
| `03.02` / `1-03.02` | 유효한 본문 편집 | `미리보기` → `03.03`. 내용이 있는 닫기 → `03.10` |
| `03.03` / `1-03.03` | 요약·본문·익명 작성자 안내를 읽기 전용으로 표시 | `이 마음 남기기` → `03.04`. 뒤로 → 본문·커서·입력 스크롤을 보존한 편집 |
| `03.04` / `1-03.04` | 익명 공개와 수정·삭제 제한 확인 | `익명으로 남기기` → 시도 ID 생성·보관 후 `03.05`. `돌아가서 수정하기`/뒤로 → 편집 |
| `03.05` / `1-03.05` | 등록 처리 중, `남기는 중…` | 성공+postId → `03.06`, 확정 실패/결과 확인 필요 → `03.11` |
| `03.06` / `1-03.06` | 실제 성공 이후 완료 | `다른 이야기 읽어보기` → 피드 갱신 후 `04.01`. `내가 남긴 글 보기` → 같은 postId의 `06.03`. 뒤로 → `04.01` |
| `03.07` / `1-03.07` | 무효 입력의 미리보기 우회 또는 서버 입력 검증 오류 | 입력 아래 오류. 유효해지면 오류 제거. 본문·닫기·미리보기 동작은 편집기와 동일 |
| `03.08` / `1-03.08` | 본문이 입력 영역 높이를 초과 | 입력 영역만 스크롤. 본문·닫기·미리보기 동작은 편집기와 동일 |
| `03.09` / `1-03.09` | 계정별 저장 초안 발견 | `이어서 쓰기` → 편집 복원. `새로 시작하기` → 별도 삭제 확인 후 삭제 성공 시 `03.01`. 뒤로 → 진입 화면의 탭·글·스크롤 |
| `03.10` / `1-03.10` | 내용 있는 편집기에서 나가기 | `계속 작성하기`/뒤로 → 편집 복원. `나중에 쓰기` → 저장 성공 확인 후 `04.01` |
| `03.11` / `1-03.11` | 등록 실패 확정 또는 기존 결과 확인 필요 | `다시 시도하기` → `03.12`. `글로 돌아가기`/뒤로 → 실패 확정 후 편집. 결과 불명이면 기존 결과 확인 우선 |
| `03.12` / `1-03.12` | 원래 등록의 상태 확인·재요청, `다시 남기는 중…` | 성공+기존 postId → `03.06`, 확정 실패/결과 확인 필요 → `03.11` |

`03.01`, `03.02`, `03.07`, `03.08`은 동일 편집기의 상태다. 화면마다 URL과 별도 입력 사본을 만들지 않는다. 공개 확인과 미리보기 단계에는 `createPost` 요청이 없다.

### 편집·초안·복귀

한글 조합을 마치기 전에 입력을 자르지 않는다. 조합 완료·붙여넣기에서 공통 문자 계산 규칙을 적용하며, 빈 값·공백·줄바꿈만 있는 값은 미리보기로 진행하지 못한다. 카운터는 화면에 보존한 입력 원문을 기준으로 계산한다. 유효성 오류는 입력 아래에 표시하고 조건이 충족되면 즉시 지운다.

초안 저장 실패는 `초안을 저장하지 못했어요.`로 알리고 메모리의 본문을 유지한다. 재시도 없이 조용히 빈 입력으로 덮어쓰지 않는다. `새로 시작하기`는 `새로 시작하면 이전 초안이 삭제돼요.` 확인을 거쳐야 한다. 취소하면 초안을 유지하고, 삭제 실패 역시 기존 초안과 오류를 남긴다.

키보드가 열려 있을 때 첫 뒤로는 키보드만 닫는다. 그다음 닫기에서 내용이 있으면 `03.10`을 연다. `나중에 쓰기`의 저장 실패는 현재 화면에 남기고 재시도 또는 명시적 미저장 이탈 확인을 제공한다. 정상 저장을 보장할 수 없는 상태에서 저장됐다고 안내하지 않는다.

### 등록 결과와 인증 예외

| 상태·사건 | 처리 |
| --- | --- |

| 성공 | 해당 초안·시도를 정리하고 MY 목록 무효화. 완료 뒤로에서 제출 화면을 복원하지 않음 |

### 디자인과 문구

`2-03`의 카드·본문 입력·확인·진행·완료 표현과 [디자인 시스템](design-system.md)을 적용한다. `03.01/02`의 안내는 `지금 떠오른 그 사람에게, 남기지 못한 말을 적어보세요.`이고, `03.07/08`에는 `그 사람에게 전하고 싶은 말이 있나요?`가 쓰인다. 같은 편집기라도 자료에 제시된 상태별 카피를 임의로 통일하지 않는다.

오류는 입력 테두리와 `한 글자라도 적어주세요.`를 함께 표시한다. 미리보기의 요약은 한 줄이며 폭을 넘으면 말줄임한다. 본문 줄바꿈은 보존한다. 긴 본문은 입력 영역 안에서 스크롤하고 카운터·경고·CTA를 덮지 않는다. 디자인의 `46`, `228` 등 카운터 예시는 고정 데이터가 아니다.

## 3. 구현 설계 — Tech Spec

### 책임과 상태 소유

아래 파일 배치는 구현 제안이며 아직 생성하지 않았다. 상태·폼·서버 캐시 라이브러리도 이번 문서화로 선정하지 않는다.

| 예정 책임 | 위치·상태 소유 |
| --- | --- |
| 라우팅·인증 복귀·피드/MY 연결 | `src/app/`의 진입점·상위 조합에서 연결 |
| 편집·미리보기·공개 확인·완료 화면 | `src/features/writing/`의 화면과 전용 컴포넌트 |
| 작성 세션 | 같은 기능의 상태 조합. 본문, 커서, 입력 스크롤, 현재 단계, 오류, 저장 상태를 소유 |
| 본문 검증·요약 | React와 분리한 순수 계산. 서버와 동일한 문자 분할·요약 규칙 검증 |
| 초안 저장·복원 | writing이 계정별 저장 데이터를 소유하고 공통 저장 도구를 사용 |
| 등록 연산·오류 변환 | writing API 어댑터. 화면은 HTTP를 직접 호출하지 않음 |
| 작성 후 목록 갱신 | 상위 조합에서 피드·MY 갱신을 알림. 기능 내부끼리 직접 import하지 않음 |

본문은 작성 세션의 한 원본으로 유지하고 미리보기에는 그 값을 전달한다. 저장된 초안에는 복원에 필요한 본문·커서·입력 스크롤·소유 계정을 연결한다. 등록 시도 ID와 제출 본문은 결과를 확정할 때까지 보관한다. 계정 전환·세션 만료에서 이전 계정의 초안이나 미확정 시도를 다른 계정에 넘기지 않는다.

초안 저장 주기·삭제 조건·자동 만료 여부는 서비스 규칙을 따른다. 저장을 예약한 타이머는 이탈 전 반영 여부를 확인하고 정리한다. 저장소 쓰기 실패나 페이지 종료 시점에 잃을 수 있는 입력을 검증한다. 구체적인 저장 엔진, 스키마 버전과 네이티브 저장 범위는 구현 전에 정한다.

### 데이터·외부 연동

논리 계약은 [서비스 계약](service-contracts.md)의 `createPost(body, submissionId)`와 `getSubmission(submissionId)`를 사용한다. 실제 endpoint·인증 전달·서버 저장 방식은 아직 확인하지 않았다. mock이 같은 계약을 구현하더라도 서버 연동 완료로 보고하지 않는다.

서버는 인증·동의·본문을 다시 검증하고 같은 사용자와 시도 ID에 게시글을 최대 한 개만 생성한다. 클라이언트 버튼 잠금만으로 중복 방지를 완료했다고 보지 않는다. `PENDING`, `SUCCEEDED(postId)`, `FAILED`, `UNKNOWN`을 구분하여 성공·확정 실패·결과 불명을 처리한다.

카운터와 요약은 [서비스 규칙](../policy/service-rules.md)의 INPUT/SUMMARY를 동일하게 적용한다. 검증 때 사용자 인식 문자 999/1,000/1,001자와 요약 19/20/21자를 비교한다. 줄바꿈·공백 정리는 요약용 계산에만 적용하고 원문 본문은 보존한다. 등록 성공 후 표시할 요약과 본문은 서버 계약과 일치해야 한다.

유효성 오류는 해당 입력에 연결하고, 인증 만료는 복귀 의도로 전환한다. 네트워크·서버 오류는 기존 본문과 시도를 유지한다. 내부 오류 메시지·인증 값·본문을 사용자 메시지나 로그에 무분별하게 노출하지 않는다.
