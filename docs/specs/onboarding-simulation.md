# 첫 방문과 감정 시뮬레이션

## 문서 정보

- 유형: 화면·사용자 흐름
- 명세 상태: 초안. 전달 자료의 출시 1차 기준은 반영했으며, 저장 구현과 일부 복구 UX는 미정이다.
- 구현 상태: 화면 연결 골격 구현(장면·CTA 전이·작성 진입). 배정 저장·진행 복원·리소스 상태는 미착수
- 검증 상태: 일부 확인. 자료 대조 완료, 기능 검증 미실행
- 갱신일: 2026-10-21
- 입력 자료: `구현 기준 v1 · 2026.10.20`의 `0-00`~`0-06`, `1-00.00`, `1-02.01`~`1-02.15`, 디자인 가이드 `2-02`. 파일명·해시는 [자료 목록](../references/tomyx-2026-10-20/README.md), 화면별 원문은 [개발 명세 추출본](../references/tomyx-2026-10-20/screens.md)에서 확인한다.
- 확정 근거: 사용자가 제공한 Desktop ToMyX 자료. 자료가 자체적으로 채택한 구현 기본값과 기존 UI에서 정한 사항을 구분하며, 이번 문서화가 실제 구현·운영 검증을 뜻하지는 않는다.
- 관련 스펙: [제품 전체 구조](product-overview.md), [글쓰기](story-writing.md), [서비스 계약](service-contracts.md), [디자인 시스템](design-system.md), [프론트엔드 아키텍처](frontend-architecture.md)
- 관련 정책: [서비스 규칙](../policy/service-rules.md)의 첫 방문·접근 권한·진행 보관, [출시 운영](../policy/launch-operations.md)의 자산 준비

## 1. 목적과 범위 — PRD

처음 방문한 사용자가 카톡·인스타·자니 중 한 장면을 경험하고, 떠오른 마음을 글로 남기거나 피드를 둘러보도록 연결한다. 장면 속 프로필과 대화는 서비스 안의 연출이다. 실제 상대를 찾거나 외부 앱으로 메시지를 보내는 기능은 포함하지 않는다.

범위는 15개 장면, A/B 선택, 진행 복원, 글쓰기 인증 연결과 피드 이탈이다. `1-00.00`의 랜딩은 LEGACY이므로 구현에서 제외한다. 15개 화면 번호는 상태 식별자이며 15개 URL을 요구하지 않는다.

| ID | 요구사항·적용 조건 | 근거·정책 연결 | 상태 |
| --- | --- | --- | --- |
| SIM-R01 | 일반 첫 방문은 별도 랜딩 없이 준비된 에피소드 진입 화면으로 이동한다. 공유 링크와 기존 진행을 먼저 확인한다. | `0-00`, `0-03`, `0-04 D-01`, 서비스 규칙의 첫 방문 | 자료 기준 확정 |
| SIM-R02 | 카톡·인스타·자니는 같은 확률로 배정하며, 진행 중 다른 에피소드로 다시 배정하지 않는다. | `1-02.01/06/11`, 서비스 규칙의 진행 보관 | 자료 기준 확정 |
| SIM-R03 | 명시된 CTA로만 장면을 이동한다. 장면 내부의 검색·발송·저장·공유 아이콘은 외부 서비스 동작을 하지 않는다. | `1-02.01`~`15`의 F1 | 자료 기준 확정 |
| SIM-R04 | 로그인 없이 경험하고 이탈할 수 있다. 글쓰기 진입에서 인증·동의·초안 분기를 적용한다. | `0-01 AUTH/RETURN`, `0-04 D-01/D-03`, 각 B·여운 화면 E1 | 자료 기준 확정 |
| SIM-R05 | 글쓰기에는 시뮬레이션 문구를 자동으로 넣지 않는다. 기존 초안이 없다면 빈 본문으로 시작한다. | 각 장면 F3, `1-03.01` | 자료 기준 확정 |
| SIM-R06 | 리소스를 실제로 준비한 뒤 진행하며, 실패하면 같은 장면에서 재시도한다. | 각 장면의 화면 상태 | 자료 기준 확정 |

### 장면과 CTA

아래 표는 원본 이벤트의 정상 전이를 묶은 것이다. 실패하면 현재 장면·대상·진행을 유지하고 오류를 안내한다. 재시도에서도 같은 에피소드를 사용한다.

작성 진입은 비로그인이면 `08.02`다. 로그인과 필수 동의를 마치면 초안이 있을 때 `03.09`, 없을 때 `03.01`로 이동한다. 이미 로그인한 사용자에게도 같은 초안 분기를 적용한다. 인증 취소·실패는 작성 실행으로 간주하지 않는다.

시스템 뒤로는 같은 에피소드의 직전 장면을 복원한다. 에피소드의 첫 장면에서 뒤로 가면 `04.01`로 나간다. 피드 접근을 게시글 등록 성공에 종속시키지 않는다. 웹에서 이전 탐색 이력이 없는 경우에도 이 규칙을 구현할 수 있도록 앱 내부 복귀 경로를 관리한다.

| 상태 | 화면 표시 | 동작 |
| --- | --- | --- |
| 리소스 준비 중 | 현재 장면의 로딩 | CTA 비활성, 준비 완료 전 자동 진행 없음 |
| 정상 | 해당 장면의 배경·상황 카드·서사·CTA | 표에 있는 전이만 허용 |
| 리소스 실패 | 현재 장면의 오류·다시 불러오기 | 에피소드·진행을 유지한 재시도 |
| 저장된 진행 복원 | 기존 장면과 분기 | 새 배정 금지. 저장 손상·복구 실패의 상세 UX는 미정 |
| 글쓰기 인증 중 | 작성용 로그인 흐름 | 원래 장면을 복귀 의도에 보관. 취소 시 작성하지 않음 |

### 디자인 적용

`2-02`의 15개 UI를 기준으로 상단 `To My X`, 배경 이미지와 어두운 오버레이, 상황을 재현한 카드, 서사 텍스트, 하단 CTA를 구성한다. 카톡·인스타·자니의 상황 카드는 기능 전용 표현이며 실제 외부 앱 UI를 실행하는 영역이 아니다.

카톡·인스타·자니의 B 및 여운 장면에는 `떠오른 말이 있다면, 여기 남겨보세요.`와 `이 마음 남기기`가 있다. 장면 문구와 CTA를 임의로 고치지 않는다. 이미지 속 샘플 프로필·숫자·시각을 실제 사용자 정보로 해석하거나 자동 수집하지 않는다. 공통 색상·서체·간격은 [디자인 시스템](design-system.md)을 따른다.

## 3. 구현 설계 — Tech Spec

### 책임과 상태

아래는 기존 [아키텍처](frontend-architecture.md)에 맞춘 구현 제안이다. 파일은 아직 만들지 않았다.

| 예정 책임 | 위치·수명 제안 |
| --- | --- |
| 앱 진입 분기와 작성·피드 연결 | `src/app/`의 얇은 진입점에서 공유 링크·인증·이력 정보를 조합 |
| 장면 표시·CTA·리소스 상태 | `src/features/onboarding/`의 화면과 전용 컴포넌트 |
| 배정·전이·진행 복원 | 같은 기능의 상태 처리. 에피소드와 화면 ID를 명시해 잘못된 조합을 방지 |
| 진행 저장소 | 기능이 공통 저장 도구를 호출. 웹 브라우저 범위의 지속 저장이며 초안 저장과 별도 책임 |
| 인증 완료 후 작성 분기 | 라우트 또는 상위 조합 지점에서 연결. onboarding에서 writing 기능 내부를 직접 import하지 않음 |

저장에 필요한 최소 정보는 에피소드, 선택 분기, 현재 장면, 완료·둘러보기 여부다. 저장 형식·버전·키는 미정이다. 장면을 이동할 때 저장하고 새 세션에서도 복원한다. 저장소를 확인하는 동안 새로운 에피소드를 먼저 배정해 화면이 바뀌지 않도록 한다.

원문에 시뮬레이션 생성 API나 외부 검색 API는 없다. 정해진 장면과 분기를 표시하는 기능으로 설계하며, AI 생성·추천·메시지 발송 기능을 추가하지 않는다. 일반 진입 분기는 공개 이야기 링크 계약과 인증 복귀 계약을 사용한다. 상세 연동은 [서비스 계약](service-contracts.md)에서 관리한다.

### 비동기·실패 처리

리소스 준비와 실제 장면 전환을 분리한다. 준비 실패는 오류로 남기고 타이머로 성공 처리하지 않는다. 진행 중 동일 CTA의 중복 탭으로 장면이 두 번 전환되지 않게 한다. 저장 오류가 새 배정이나 진행 초기화로 이어지지 않도록 보존·복구 방식을 구현 전에 정한다.

화면을 벗어나면 리소스 요청·타이머·이벤트 구독을 정리한다. 늦은 비동기 완료가 다른 에피소드나 현재 작성 화면을 덮어쓰지 않아야 한다. 시뮬레이션 문구·프로필을 초안이나 인증 사용자의 개인정보와 섞어 저장하지 않는다.

### 플랫폼과 품질 조건

| 대상 | 적용·차이 | 검증 환경 |
| --- | --- | --- |
| 웹 | 동일 브라우저 진행 복원, 새로고침·직접 공유 링크·브라우저 뒤로, 좁은 화면과 큰 글자 | 모바일 Safari·Chrome 및 데스크톱 브라우저. 실제 버전은 실행 시 기록 |
| Android | 공통 장면·분기를 적용하되 시스템 뒤로와 앱 종료·복귀, 지속 저장 범위를 별도 검증 | 실기기·에뮬레이터 미실행 |
| iOS | 공통 장면·분기를 적용하되 safe area·앱 종료·복귀, 지속 저장 범위를 별도 검증 | 실기기·시뮬레이터 미실행 |

터치 대상은 공통 최소 크기를 따르고, 연출용 아이콘을 작동하는 버튼으로 보조기기에 안내하지 않는다. 큰 글자에서도 서사와 CTA에 접근할 수 있어야 한다. 장면 준비 시간과 이미지 메모리는 실제 자산을 확보한 뒤 측정하며, 자료에 없는 성능 수치는 확정하지 않는다. 현재 의존성·네이티브 설정 변경은 없다.

| --- | --- | --- | --- |
| SIM-AC01 | `0-03`, `0-04 D-01`, `1-00.00` | 신규 일반 진입은 세 배정 중 하나, 기존 진행은 해당 장면, 완료·둘러본 이력은 피드, 공유 링크는 대상 이야기를 우선한다. LEGACY 랜딩이 없다. | 분기 단위 검증 + 웹 직접 진입 |

| SIM-AC03 | `02.06-AC1`, `02.07-AC1/2`, `02.08-AC1`, `02.09-AC1`, `02.10-AC1` | 인스타의 두 선택 경로와 작성 진입이 IA 표와 일치한다. | A/B 각각 수동 검증 |

## 화면 연결 골격 — 2026-10-22

`/onboarding` 한 라우트에서 에피소드를 무작위 배정하고 IA 표의 장면·CTA 전이와 글쓰기 진입(비로그인은 로그인 시트)을 mock으로 연결했습니다.

2026-10-26(진행 저장): 첫 방문 자동 배정과 복원을 구현했습니다. 저장 키는 `tomyx.onboarding.v1`, 내용은 `{episode, scene, done}`이며 웹은 localStorage, localStorage가 없는 환경(네이티브)은 앱 실행 동안의 메모리 보존으로 대체합니다(영구 저장은 OPEN-05 확정 후). 피드(`/`)는 이력이 없거나 미완료면 `/onboarding`으로 보내고, 온보딩은 저장된 에피소드·장면을 복원하며 재배정하지 않습니다(SIM-R02). 복원 장면의 뒤로 경로는 선형 그래프로 재구성합니다. 완료(done) 기록 시점은 B·여운의 작성 CTA 선택(인증 취소와 무관) 또는 첫 장면에서 뒤로 이탈(둘러보기)입니다. 손상된 저장값은 무시하고 새로 배정하며, 공유 링크(`/stories/[id]`) 직접 진입은 이 분기와 무관하게 우선합니다. 개발 환경 `?episode=` 고정 시에는 저장을 읽지도 쓰지도 않습니다.

2026-10-26: 15개 장면 전체에 연출용 상황 카드와 진입 모션을 구현했습니다. 카톡은 친구 목록이 살짝 흐른 뒤 X 프로필이 떠오르고, 인스타는 검색 타이핑 뒤 계정·새 게시물이 생기며, 자니는 검색에 X가 입력되고 대화방·보내기 직전(자니 타이핑)·꺼진 화면으로 이어집니다. 모든 전환은 페이드+상승(RN Animated timing) 스태거이며, 상황 카드는 접근성 탐색·터치에서 제외한 연출 전용입니다(SIM-R03). 개발 환경 `?episode=kakao|insta|jani`로 에피소드를 고정해 검수할 수 있습니다. 실제 사진·브랜드 자산 확보 전까지 그라데이션 자리 표현을 사용합니다. 화면 내 뒤로는 같은 에피소드의 직전 장면을 복원하고 첫 장면에서는 피드로 나갑니다. 진행 저장·복원(SIM-R02의 재배정 금지 포함), 리소스 준비·실패 상태, 첫 방문 자동 진입 분기는 미구현이며 저장 설계 확정 후 진행합니다. 서사 문구는 디자인 추출본 기준 근사치로, 원본 Figma 문구와의 최종 대조(SIM-AC08)가 남아 있습니다. 전이 그래프는 `scripts/onboarding.test.mjs`로 검증합니다.
