## 1. 목적과 범위 — PRD

사진·여백·서체로 감정을 전달하는 모바일 중심 화면을 웹·Android·iOS에서 일관되게 구현합니다. 컴포넌트의 모양뿐 아니라 선택·오류·처리 중·접근성 상태까지 같은 기준으로 관리합니다.

이번 문서는 공통 UI의 책임과 필요한 상태를 정리합니다. 새로운 컴포넌트 라이브러리나 스타일링 도구를 선택하거나 설치하지 않습니다. 아래 컴포넌트 이름은 구현 제안이며 현재 코드에 존재한다는 뜻이 아닙니다.

| ID | 요구사항 | 근거·상태 |
| --- | --- | --- |
| UI-01 | 어두운 배경, 밝은 본문, 사진 위 명암 처리, 둥근 버튼·시트를 전달 UI에 맞춘다. | 디자인 가이드에서 확인한 시각 구성 |
| UI-02 | 입력·선택·오류·비활성·처리 중을 구분하고, 색 외에도 상태를 알린다. | `0-01` VISUAL, `2-00` |
| UI-03 | 좁은 화면·키보드·큰 글자에서도 본문과 CTA에 접근한다. | `0-01` VISUAL·NAV |
| UI-04 | 원문의 예시 데이터·기기 상태바·개발 설명을 제품 UI와 구분한다. | `0-00`, `0-02`, `0-06` |

## 2. 화면 구성과 상태 — IA

### 공통 레이어

화면 바탕 위에 사진 또는 콘텐츠를 두고, 필요한 화면에는 명암 오버레이를 겹칩니다. 제목·본문·메타데이터와 버튼은 그 위에 배치합니다. 피드의 고정 컨트롤은 스크롤되는 이미지·본문과 분리합니다. 시트가 열리면 배경의 터치와 접근성 탐색을 잠급니다.

원문의 `9:41`, 노치, 배터리, 홈 인디케이터는 기기 목업입니다. 웹에 가짜 시스템 상태바를 그리는 요구사항으로 해석하지 않습니다. 네이티브에서는 실제 시스템 영역과 safe area에 대응합니다. 화면 아래 설명 카드와 Dev 링크도 사용자 화면에 넣지 않습니다.

### 시각 상태와 실제 초기 상태

디자인의 선택된 신고 사유·체크된 동의·켜진 Push는 상태 예시입니다. 실제 초기값은 정책을 따릅니다. 동의와 신고 사유는 미선택으로 시작하며, Push는 지원·권한·서버 저장 상태로 판단합니다. 공감·알림 읽음도 실제 데이터로 표시합니다.

## 3. 구현 설계 — Tech Spec

### 디자인 토큰

`2-00`은 버튼·입력·탭·아이콘 등의 시각 보드입니다. 추출 가능한 텍스트에는 색상 HEX, 폰트별 크기·굵기·행간, 반경·간격의 이름과 값이 없습니다. PDF 화면에서 색을 뽑거나 비율을 재서 확정된 토큰 값으로 기록하지 않습니다.

| 분류 | 현재 확인한 기준 | 추가로 받아야 할 정의 |
| --- | --- | --- |
| 색상 | 검은 계열 화면, 따뜻한 어두운 표면, 밝은 본문, 약한 보조 글자, 붉은 위험/오류 표시 | semantic color의 실제 값, 상태별 대비와 투명도 |
| 서체 | `0-06`에 Pretendard·MaruBuri 명시 | 실제 파일·사용 조건·weight, 제목/본문/UI별 대응, 크기·행간·자간·fallback |
| 배치 | 기준 뷰포트 375×812, 기본 좌우 여백 24px, 상·하단 safe area | 넓은 웹 최대 폭·정렬, 태블릿·가로 화면 대응 |
| 조작 영역 | 최소 터치 영역 44×44 | 아이콘 시각 크기와 실제 누름 영역의 구분 |
| 형태 | 둥근 버튼·표면·시트, 테두리·구분선 | radius·border width·그림자 수치 |
| 배경 | 사진과 하단 명암 오버레이, 단색 화면 | 원본 이미지·크롭 기준·해상도·오버레이 stop/opacity |
| 움직임 | 상태 전환과 스크롤에 따른 컨트롤 변화 | 시간·easing·전환 효과·동작 줄이기 대응 |

위 수치는 `0-01`의 원문 기준입니다. 웹의 CSS px와 네이티브 레이아웃 단위 적용 결과는 각 플랫폼에서 검증합니다. 현재 `src/constants/theme.ts`는 Expo 템플릿 값이므로 이 디자인이 반영됐다고 보지 않습니다. 실제 도입 시 `src/theme/`로 옮길 범위를 정하고 토큰 원본을 중복 유지하지 않습니다.

### 상태와 플랫폼 책임

- 디자인 토큰은 `src/theme/`, 여러 기능이 쓰는 UI는 `src/components/`, 전용 조합은 `src/features/<기능>/components/`에 둘 예정입니다. 실제 파일은 구현할 때 만듭니다.
- 표시 컴포넌트는 상태와 콜백을 받습니다. 인증·조회·게시 요청을 직접 실행하지 않습니다.
- 스크린리더 이름·역할·선택/비활성 상태, 키보드 탐색, 시트 초점 이동과 호출 버튼 복원을 검수합니다. 숨긴 컨트롤은 포커스와 접근성 탐색에서도 제외합니다.
- 네이티브와 웹의 화면 높이·키보드·뒤로 가기·폰트 렌더링 차이는 공통 UI 밖의 필요한 경계에서 처리합니다. 화면마다 플랫폼 분기를 복제하지 않습니다.
- 사진·음원·폰트는 사용 가능한 실제 자산을 확보한 뒤 목록에 출처·사용 조건·경로를 남깁니다. 참고 PNG를 제품 배경이나 아이콘으로 재사용하지 않습니다.

| 플랫폼 | 검증 항목 | 현재 상태 |
| --- | --- | --- |
| 웹 | 모바일 브라우저 높이 변화, 키보드, 폰트 로딩, 넓은 화면, 키보드·스크린리더 탐색 | 미실행 |
| Android | 시스템 뒤로·키보드, safe area, 글자 확대, 폰트와 터치 영역 | 미실행 |
| iOS | safe area, 키보드, Dynamic Type 대응, 모달 초점, 폰트 | 미실행 |

### 원문 사이의 차이

`04.02` 디자인에는 벨과 음소거 아이콘이 남아 있지만 개발명세 `04.02-F2`와 공통 SCROLL은 벨·소리·탭을 숨기고 +만 남기도록 명시합니다. +의 크기·위치도 시각 보드에서는 기본 화면과 다르게 보입니다. 동작 구현은 명시된 규칙을 기준으로 준비하되, 디자인 일치 완료 판정 전 디자이너가 스크롤 후 UI를 맞춰야 합니다.

`04.04`에는 + 버튼이 보이지만 해당 동작 표에 쓰기 이벤트가 없습니다. [피드 명세](story-feed.md)의 미결정 사항에서 목적지를 확인합니다. `09.06` 등 일부 디자인 미리보기는 배경·내용 판독에 한계가 있어 원본 Figma 또는 개별 화면을 함께 확인해야 합니다.

## 7. 04.01~04.04 mock 구현 기준 — 2026-10-21

이번 검수용 임시 토큰 원본은 `src/theme/tokens.ts`입니다. 배경 `#15130f`, 표면 `#302d27`, 본문 `#f5efe3`, 보조 글자 `#b8b0a2`, 기본 여백 24, 웹 최대 폭 480을 사용합니다. 제목 26/37, 본문 16/28, UI 11~14 크기와 행간은 확정 디자인 토큰이 아닌 구현 제안입니다. 스크롤은 연속 방식이며 긴 글은 카드 높이가 늘어나 본문이 잘리지 않습니다.
