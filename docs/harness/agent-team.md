# 에이전트 운영 방식

Claude Code와 Codex는 같은 [공통 지침](../../AGENTS.md)과 저장소 문서를 사용합니다. 특정 도구의 대화 이력이나 자동 메모리는 보조 수단이며, 프로젝트 지식의 원본은 저장소에 둡니다.

## 운영 원칙

- 현재 요청을 맡은 에이전트가 범위, 구현, 검증, 문서 동기화와 최종 보고를 책임집니다.
- 아래 역할은 검토 관점입니다. 역할마다 별도 에이전트를 실행할 필요는 없습니다.
- 작은 작업은 한 에이전트가 처리합니다. 실제 위임·병렬 실행은 사용자 요청이나 적용되는 운영 지침에서 허용한 범위에서만 사용합니다.
- 다른 에이전트의 결과도 변경 파일과 검증 근거를 직접 확인한 뒤 통합합니다.
- Claude와 Codex가 같은 파일을 동시에 수정하지 않습니다. 같은 PC에서도 공유 작업 폴더와 Git 인덱스가 충돌할 수 있습니다.

## 역할과 책임

| 역할 | 적용할 때 | 책임과 산출물 |
| --- | --- | --- |
| 작업 책임자 | 모든 작업 | 목적·범위·완료 조건 정리, 결과 통합, 남은 문제와 다음 작업 보고 |
| 프론트엔드 개발 | 화면·라우팅·API 연동·상태 변경 | 관련 명세 확인, 웹과 네이티브 구현, 로딩·오류·접근성 처리 |
| 품질 검증 | 기능·버그·공통 코드 변경 | 재현 조건, 완료 조건별 결과, 회귀 위험과 플랫폼별 미검증 항목 확인 |
| 문서 관리 | 명세·코드·운영 규칙 변경 | 문서 동기화, 결정 근거·실수 기록·인수인계 갱신 |
| 개발 환경·빌드 관리 | 의존성·환경변수·Expo·EAS 설정 변경 | SDK 호환성, 실행·빌드 영향, 설정과 절차의 일치 확인 |

## 작업 순서

1. [인수인계](handoff.md)와 관련 명세를 읽고 Git 상태를 확인합니다.
2. [정책](../policy/README.md)의 의도와 규칙, [통합 스펙](../specs/README.md)의 PRD·IA·Tech Spec과 완료 조건을 함께 확인합니다. 기획·디자인 자료의 사실과 해석을 구분하고, 미확정 사항은 가정으로 표시하거나 필요한 질문을 합니다.
3. 필요한 역할의 관점으로 변경과 검증 방법을 정합니다.
4. 구현 후 실제 diff와 검증 결과를 확인합니다. 기능별 완료 조건에 맞춰 필요한 플랫폼을 검증합니다.
5. [문서 동기화](documentation-sync.md)를 수행하고 인수인계를 갱신합니다.
6. 변경 내용, 검증 결과, 미해결 문제를 사용자에게 보고합니다.

웹을 우선 검증하되 공통 코드나 네이티브 설정을 바꿨다면 Android·iOS 영향을 확인합니다. 기기가 없거나 실행하지 못한 플랫폼은 검증 완료로 표시하지 않습니다.

## Claude·Codex와 PC 간 교대

작업을 넘기는 에이전트는 [인수인계](handoff.md)에 다음 내용을 남깁니다.

- 작업 목적과 현재 완료 범위
- 변경한 파일과 관련 명세
- 확정 사항과 미결정 사항
- 검증 명령어·결과·대상 환경
- 남은 문제와 다음 작업

같은 PC에서 도구만 바꿀 때도 미커밋 변경을 확인합니다. 다른 PC로 옮길 때는 필요한 코드와 문서가 커밋·푸시돼 있어야 합니다. 자동 메모리, 무시된 파일, 로컬 변경은 원격 저장소만으로 전달되지 않습니다.

새 에이전트는 저장소와 브랜치, 작업 폴더의 변경을 확인한 뒤 최신 원격 기록을 가져옵니다. 미커밋 변경이 있는 상태에서 무조건 pull하거나 초기화하지 않습니다. 기존 작업을 보존한 뒤 대상 브랜치를 맞추고, 인수인계 내용을 실제 파일과 다시 비교합니다.

## 병렬 작업을 사용할 때

- 서로 독립적인 작업만 분리하고 수정 파일의 책임자를 정합니다.
- 같은 파일을 수정하거나 선행 결정에 의존하는 작업은 순서대로 처리합니다.
- 별도 브랜치나 worktree가 필요하면 사용하고, 최종 통합은 작업 책임자가 맡습니다.
- 위임 시 목적, 관련 명세, 수정 가능 범위, 완료 조건, 검증 방법을 전달합니다.
- 병합 후 통합된 코드에서 다시 필요한 검증을 수행합니다.

## 완료 기준

- 요청한 범위와 명세의 완료 조건을 충족했는가?
- 다른 작업자의 변경을 보존했는가?
- lint·타입 검사와 필요한 기능 검증을 수행했으며, 실패·미실행을 구분했는가?
- 관련 문서와 인수인계가 현재 코드·설정과 일치하는가?
- 새 문서가 Git 공유 대상에 포함되는가?

이 문서 자체가 훅이나 CI를 실행하지는 않습니다. 자동 검증 도구가 구축되기 전에는 에이전트가 절차를 수행하고 실제 결과를 기록합니다.
