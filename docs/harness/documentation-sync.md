# 문서 동기화

코드, 명세, 검증 결과를 같은 작업 안에서 갱신합니다. 문서 변경이 필요 없는 작업은 그 이유를 확인하고, 의미 없는 수정 이력을 만들지 않습니다.

## 작업 시작 전

- [문서 목록](../README.md)과 [인수인계](handoff.md)를 읽고 이번 작업의 범위를 확인합니다.
- [실수 기록](mistakes.md)에서 관련 재발 방지 규칙을 확인합니다.
- [에이전트 운영](agent-team.md)에 따라 현재 작업 책임자와 수정 범위를 정합니다.
- 관련 명세와 코드를 비교해 확정 사항, 가정, 불일치를 구분합니다.
- `git status --short --branch`로 기존 변경을 확인합니다. 다른 작업자의 변경을 덮어쓰지 않습니다.

## 수정 전: 함께 갱신할 문서 정하기

서비스 규칙과 의도가 바뀌면 [정책 문서](../policy/README.md)를 구현 여부와 별개로 먼저 갱신합니다. 구현이 뒤따르면 관련 [통합 스펙](../specs/README.md)의 PRD·IA·Tech Spec과 완료 조건을 함께 확인합니다. 새 문서는 각 폴더의 목록에 등록하고, 운영 문서는 [문서 목록](../README.md)에 등록합니다.

| 변경 유형 | 함께 확인할 내용 |
| --- | --- |
| 제품 요구사항·정책 | 정책 원본의 규칙·의도·근거, 이를 참조하는 통합 스펙의 PRD·IA·기술 설계·완료 조건 |
| 화면·라우트·탭·뒤로 가기 | 같은 스펙의 IA·화면 흐름·딥링크와 플랫폼별 기술 설계 |
| UI·스타일·애니메이션 | 통합 스펙의 화면 상태·기술 설계·접근성, 확정된 디자인 규칙 |
| 이미지·영상 피드 | 재생·정지 조건, 화면 밖 리소스 해제, 페이지 넘김, 측정 환경과 성능 결과 |
| API 연동·인증·상태 관리 | 요청·응답 계약, 오류 처리, 세션·저장 정책, 서버 확인이 필요한 사항 |
| 의존성·환경변수·빌드 | 설치·실행 문서, 관련 통합 스펙의 Tech Spec, 환경변수 양식, 영향받는 플랫폼 |
| 공통 구조·설계 선택 | 해당 통합 스펙의 Tech Spec·결정 기록과 이를 참조하는 문서 |
| 에이전트 작업 방식 | 해당 하네스 문서와 루트 `AGENTS.md`의 안내 |
| 커밋·코드·디자인 규칙 | 해당 `docs/conventions/` 문서와 문서 목록 |
| 실제 실수·검증 누락 | [실수 기록](mistakes.md)의 원인과 방지 규칙 |

플랫폼에서 확인하지 않은 결과를 공통 동작으로 일반화하지 않습니다. 예를 들어 웹에서 스크롤이 정상이어도 Android와 iOS까지 검증됐다고 쓰지 않습니다.

## 수정 후

- 명세의 완료 조건과 실제 변경이 일치하는지 확인합니다.
- 정책의 의도가 바뀌었다면 변경 이유·확정 근거를 정책 원본에 남깁니다. 이를 참조하는 스펙의 구현 설계와 검증 조건도 갱신합니다.
- 사용자에게 보이는 동작과 코드의 타입·설정이 맞는지 확인합니다.
- 실행한 검증의 명령어, 결과, 대상 환경을 기록합니다. 빌드 성공과 설치·실행 성공을 구분합니다.
- 화면 변경은 관련 화면 크기, 입력 방식, 접근성을 확인하고 필요한 경우 화면 캡처를 남깁니다.
- 새 문서의 링크와 경로가 유효한지 확인하고 문서 목록을 갱신합니다.
- [인수인계](handoff.md)에 미해결 문제, 다음 작업, 관련 문서를 반영합니다.

## 작업 종료·커밋·빌드 전

커밋과 빌드를 실행하기 전에는 [문서 동기화 리뷰 스킬](../skills/documentation-review/SKILL.md)을 수행합니다. 이 문서는 무엇을 동기화할지 정의하고, 스킬은 실제 변경 대조와 진행 여부 판단을 담당합니다. 실행 방식과 적용 범위는 [스킬 목록](../skills/README.md)에서 확인합니다.

커밋을 수행할 때는 [커밋 컨벤션](../conventions/commit.md)을 먼저 확인합니다.

```bash
git status --short --branch
git diff --stat
git diff
git diff --cached
git ls-files --others --exclude-standard
```

- 일반 diff에 나오지 않는 새 문서도 직접 읽습니다.
- 코드 변경에 필요한 문서가 함께 포함됐는지 확인합니다.
- 문서와 설정의 중복·모순, 끊어진 링크, 비밀값이 없는지 확인합니다.
- 필요한 문서가 전역 `.gitignore` 때문에 빠지지 않았는지 확인합니다.
- 커밋과 푸시를 요청받았다면 문서도 함께 반영하고, 인수인계 내용이 실제 작업 상태와 맞는지 확인합니다.

같은 목적의 코드와 문서는 함께 커밋하고, 관계없는 변경은 분리합니다. 검증 실패나 미실행 항목은 작업 보고에서 누락하지 않습니다.
