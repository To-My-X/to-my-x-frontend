# 인수인계

대화가 바뀌거나 다른 PC에서 작업할 때 먼저 읽습니다. 현재 상태를 짧게 유지하고, 상세 내용은 해당 명세나 결정 문서로 연결합니다. 각 작업 종료 시 갱신합니다.

## 현재 작업

- 갱신일: 2026-10-13
- 목적: 브랜치 운영 규칙 기록과 develop 생성, 초기 문서 커밋
- 단계: 문서 수정과 검증 완료. ESLint 미설정으로 lint 미검증
- 관련 문서: [문서 목록](../README.md), [공통 지침](../../AGENTS.md)

## 확정 사항

- TypeScript·React Native·Expo를 사용하고 웹을 먼저 출시한 뒤 Android·iOS로 확장합니다.
- Claude Code와 Codex를 상황에 맞게 교대로 사용합니다.
- 공통 지침은 `AGENTS.md`에, 명세와 프로젝트 지식은 `docs/`에 한국어로 관리합니다. `CLAUDE.md`는 공통 지침을 참조합니다.
- 실제 코드와 의존성 버전은 `package.json`과 `package-lock.json`, 빌드 프로필은 `eas.json`에서 확인합니다.
- 커밋은 [커밋 컨벤션](../conventions/commit.md)에 따라 한국어 메시지를 작성하고 목적별로 나눕니다. 다른 컨벤션은 개발 중 필요할 때 추가합니다.
- 서비스 기획·로직·내부 규칙과 의도·근거는 [정책 폴더](../policy/README.md)에 기록합니다. 구현 여부와 별개로 정책이 확정되거나 바뀌면 먼저 갱신합니다.
- 정책·화면·기능 등 주제별 PRD·IA·Tech Spec과 완료 조건은 [통합 스펙 폴더](../specs/README.md)의 한 파일에 작성합니다.
- 서비스 규칙과 그 변경 이유는 정책 원본에서 관리합니다. 스펙은 원본을 연결하고 해당 작업의 기획·화면 흐름·기술 설계·검증을 기록합니다.
- 프로젝트 스킬은 `docs/skills/`에 보관합니다. 커밋·빌드 전 `documentation-review` 수행을 공통 지침에서 필수로 지정했습니다. 이는 에이전트 실행 절차이며 직접 실행한 터미널 명령이나 CI의 강제 훅은 아닙니다.

- 브랜치는 [운영 규칙](../conventions/branch.md)에 따라 `main`과 `develop`을 유지합니다. 일반 개발은 `develop`, 배포는 검증 후 PR로 `main`에 반영합니다. CI/CD는 후속 작업입니다.

## 이번 변경

- 로컬 `develop`을 생성하고 해당 브랜치에서 작업합니다. 원격 브랜치 생성과 푸시는 이번 요청에 포함하지 않습니다.
- 초기 SDD·하네스 문서와 공통 스킬은 `78b200b`에 기록했습니다.
- 브랜치 역할, 임시 작업, 배포 PR, 긴급 수정과 플랫폼별 CI/CD 계획을 문서화했습니다. 브랜치 규칙은 초기 문서 구성과 별도 커밋으로 관리합니다.

## 검증

- Markdown 파일의 로컬 링크와 `git diff --check`를 확인했습니다. 두 에이전트의 스킬 링크가 같은 원본을 가리키고 Git에서 제외되지 않는 것도 확인했습니다.
- 기본 `quick_validate.py`는 로컬 Python 실행 시 Xcode 라이선스 오류로 실행하지 못했습니다. Node와 YAML 파서로 스킬의 필수 메타데이터·이름·설명과 링크를 확인했습니다.
- `npx --no-install tsc --noEmit`은 통과했습니다.
- `expo lint`는 ESLint 설정이 없어 실행하지 못했습니다. 설치 제안은 거절했으며 의존성은 변경하지 않았습니다.
- 앱 코드 변경은 없습니다. 이번 작업에서 앱 빌드·실행은 검증하지 않았습니다.
- Codex의 사용 가능한 스킬 목록에 `documentation-review`가 표시됐고 이번 커밋 준비에 적용했습니다. Claude에서의 자동 선택과 빌드 전 실행은 아직 검증하지 않았습니다.

## 남은 사항과 다음 작업

- ESLint 의존성과 설정이 없어 lint를 실행할 수 없는 상태입니다. 검증 환경을 설정할 때 해결합니다.
- 통합 스펙 양식은 준비됐고 실제 제품 스펙은 아직 없습니다. 기획·디자인 자료를 전달받으면 해당 주제의 통합 스펙을 작성합니다.
- 훅·CI·자동 테스트 환경은 이번 작업에서 구성하지 않았습니다.
- 다음 세팅 범위는 사용자의 후속 지시에 따릅니다. 현재 문서 작성만으로 SDD나 하네스 자동화가 완성된 것으로 취급하지 않습니다.
