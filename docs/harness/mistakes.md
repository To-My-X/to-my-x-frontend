# 실수 기록과 재발 방지

이 프로젝트에서 실제로 발생한 실수와 검증 누락을 기록합니다. 다음 에이전트가 같은 문제를 피할 수 있도록 원인, 방지 규칙, 확인 방법을 남깁니다.

## 기록 기준

- 에이전트의 누락·오판·범위 이탈이 확인됐거나 사용자가 이를 지적한 경우 기록합니다.
- 동작은 하더라도 명세, 문서화, 검증 절차를 빠뜨렸다면 기록합니다.
- 새로운 선호나 요구사항, 일반적인 추가 요청은 이전 작업의 실수로 취급하지 않습니다.
- 추측한 원인은 추측이라고 표시합니다. 다른 프로젝트의 사건을 이 프로젝트에서 겪은 일처럼 옮기지 않습니다.
- 같은 유형이 반복되면 기존 항목에 재발 상황과 강화한 규칙을 추가합니다.
- 해결 후에도 기록을 보존합니다. 실제 확인 없이 해결 완료로 바꾸지 않습니다.

## 기록 양식

```markdown
### YYYY-MM-DD: 문제 이름

- 상황과 영향:
- 확인한 원인:
- 조치와 현재 상태:
- 재발 방지 규칙:
- 검증 방법과 결과:
```

## 기록

### 2026-10-13: 서비스 정책 문서와 통합 스펙의 역할을 합침

- 상황과 영향: 별도의 정책 관리와 PRD·IA·Tech Spec 통합을 요청받았지만, 두 요청을 합쳐 모든 스펙을 `docs/policy/`에 두도록 구성했습니다. 사용자가 정책 관리 요구가 어디에 반영됐는지 다시 확인해야 했습니다.
- 확인한 원인: 문서 종류를 통합하라는 요청을 문서의 목적까지 합치라는 의미로 해석했습니다.
- 조치와 현재 상태: `docs/policy/`는 서비스 규칙과 의도·근거, `docs/specs/`는 주제별 통합 구현 명세로 분리했습니다. 스펙에서 정책 원본을 참조하도록 지침과 양식을 수정했습니다.
- 재발 방지 규칙: 사용자가 구분한 문서의 책임을 먼저 확인합니다. PRD·IA·Tech Spec의 통합과 정책 기록의 독립성을 함께 유지하고, 정책 본문은 중복 정의하지 않습니다.
- 검증 방법: 정책 관리 안내, 스펙 양식, 문서 목록, 에이전트 지침에서 두 문서의 역할과 참조 경로가 일치하는지 확인합니다.

### 2026-10-13: 린트 검증 중 의도하지 않은 의존성 설치 시작

- 상황과 영향: `.gitignore` 변경 검증 중 `expo lint`를 비대화형으로 실행했습니다. ESLint가 없는 상태에서 자동 설치가 시작돼 `package.json`에 의존성이 추가됐습니다.
- 확인한 원인: 검증 명령이 초기 설정까지 수행할 수 있다는 점을 확인하지 않았습니다.
- 조치와 현재 상태: 설치를 중단하고 해당 실행이 추가한 의존성만 제거했습니다. ESLint는 여전히 미설정이며 lint는 미검증 상태입니다.
- 재발 방지 규칙: 검증 전에 도구와 설정의 유무를 확인합니다. 미설정 상태에서 자동 설치를 유발하는 비대화형 실행을 피하고, 이번 작업에 포함되지 않은 환경 설정을 임의로 추가하지 않습니다.
- 검증 방법과 결과: 이후 대화형 실행에서 설치를 거절하자 `ESLint is not configured for this project.`로 종료됐습니다. 검증 전후 `package.json`, 잠금 파일, 설정 파일의 diff를 확인합니다.

### 2026-10-13: 전역 Git 제외 규칙으로 공통 지침이 공유 대상에서 빠짐

- 상황과 영향: 프로젝트 루트에 `AGENTS.md`와 `CLAUDE.md`가 있었지만 Git 상태에 나타나지 않아, 초기 푸시에 포함되지 않았습니다.
- 확인한 원인: 이 PC의 전역 Git 제외 파일이 두 이름을 제외하고 있었습니다.
- 조치와 현재 상태: 프로젝트 `.gitignore`에 두 루트 파일의 예외 규칙을 추가했고, Git 상태에서 새 파일로 표시되는 것을 확인했습니다. 원격 반영 여부는 커밋·푸시할 때 별도로 확인해야 합니다.
- 재발 방지 규칙: 문서가 로컬에 존재하는 것과 Git으로 공유된 것을 구분합니다. 새 문서는 Git 상태를 확인하고, 보이지 않으면 `git check-ignore -v <경로>`로 원인을 찾습니다.
- 검증 방법: 커밋 전에는 `git status --short`, 커밋 후에는 `git ls-files AGENTS.md CLAUDE.md`로 확인합니다. 다른 PC에서는 푸시된 브랜치를 가져온 뒤 파일을 확인합니다.

### 2026-10-14: 로컬 생성 파일에 의존한 타입 검사

- 상황과 영향: 로컬 타입 검사는 통과했지만 첫 Actions 실행에서 CSS import 타입을 찾지 못해 웹 배포가 중단됐습니다.
- 확인한 원인: Git에서 제외하는 expo-env.d.ts의 Expo 타입 참조가 로컬에만 존재했습니다.
- 조치와 현재 상태: src/types/expo.d.ts에 Expo 타입을 참조해 깨끗한 runner에서도 읽도록 수정했습니다. 생성 파일을 제거한 로컬 검사와 Actions check job이 통과했습니다.
- 재발 방지 규칙: CI 최초 연결 시 생성·무시된 파일에 의존하는 검증을 확인하고 깨끗한 환경에서 검사합니다. 자동 생성 파일을 무조건 Git에 추가하지 않습니다.
- 검증 방법과 결과: expo-env.d.ts가 없는 상태에서 npm run typecheck 통과. Actions 실행 38521762369의 check job 통과.

### 2026-10-15: fingerprint 자동화에서 로컬 의존성 변형을 검증하지 않음

- 상황과 영향: 로컬 Android 작업 후 변형된 node_modules의 fingerprint로 EAS production 빌드를 요청해 Configure expo-updates 단계에서 실패했습니다.
- 원인: 로컬 의존성에 추가된 Gradle wrapper·SDK 파일과 수정된 Manifest를 깨끗한 npm 설치와 비교하지 않았습니다.
- 조치: 동일 잠금 버전 원본과 파일 단위 비교 후 npm ci로 복원하고 머신별 local.properties만 fingerprint에서 제외했습니다.
- 재발 방지: 런타임 불일치는 로그의 source diff를 확인하고 원본 패키지와 대조합니다. 네이티브 소스·패키지 전체를 무시해 해결하지 않습니다.
- 검증: 원본 4개 패키지의 해시가 실패한 EAS 로그의 클라우드 해시와 일치함을 확인했습니다. 수정 후 testing 빌드 dd216c2f-a799-4ec6-8e75-3396929fae61가 성공했습니다. 사용자가 Android 내부 테스트 수동 출시 완료를 확인했습니다.

### 2026-10-21: 새 문서의 공백 검사가 일반 diff에서 빠짐

- 상황: 참고 자료 Markdown을 추가한 뒤 일반 `git diff --check`는 통과했지만, 스테이징 후 원문 3개의 끝 빈 줄이 검출됐습니다.
- 원인: 아직 추적하지 않는 파일은 일반 diff 검사 대상이 아닙니다.
- 조치·재발 방지: 끝 빈 줄을 정리하고 staged diff를 다시 검사했습니다. 새 파일의 검증은 내용 확인과 함께 `git diff --cached --check`까지 수행하며, 일반 diff 결과로 새 파일 검증을 대신하지 않습니다.

### 2026-10-22: Hermes 미지원 API를 웹 검증만으로 통과시킴

- 상황과 영향: 글쓰기 글자 수 계산에 `Intl.Segmenter`를 모듈 로드 시점에 사용했습니다. 웹·Node 테스트는 통과했지만 Hermes(iOS·Android)에는 Segmenter가 없어 네이티브 앱이 시작 즉시 크래시하는 상태로 커밋·OTA까지 발행됐습니다.
- 원인: 웹과 Node에서만 검증하고 네이티브 JS 엔진의 API 지원 차이를 확인하지 않았습니다.
- 조치: Segmenter가 없으면 코드 포인트 분할로 폴백하도록 수정하고 iOS 시뮬레이터에서 피드·편집 화면 렌더를 확인했습니다.
- 재발 방지: 표준이어도 비교적 새로운 JS API(Intl 계열, 신형 String/Array 메서드)를 쓰면 Hermes 지원 여부를 확인하고, 네이티브 번들에 포함되는 변경은 최소 한 플랫폼의 시뮬레이터/기기 실행을 검증에 포함합니다. 특히 모듈 최상위에서 실행되는 코드는 앱 전체 크래시로 이어지므로 주의합니다.
