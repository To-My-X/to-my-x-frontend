# 실수 기록과 재발 방지

이 프로젝트에서 실제로 발생한 실수와 검증 누락을 기록합니다. 다음 에이전트가 같은 문제를 피할 수 있도록 원인, 방지 규칙, 확인 방법을 남깁니다.

## 기록 기준

- 에이전트의 누락·오판·범위 이탈이 확인됐거나 사용자가 이를 지적한 경우 기록합니다.
- 동작은 하더라도 명세, 문서화, 검증 절차를 빠뜨렸다면 기록합니다.
- 새로운 선호나 요구사항, 일반적인 추가 요청은 이전 작업의 실수로 취급하지 않습니다.
- 추측한 원인은 추측이라고 표시합니다. 다른 프로젝트의 사건을 이 프로젝트에서 겪은 일처럼 옮기지 않습니다.
- 같은 유형이 반복되면 기존 항목에 재발 상황과 강화한 규칙을 추가합니다.
- 해결 후에도 기록을 보존합니다. 실제 확인 없이 해결 완료로 바꾸지 않습니다.

## 기록 양식

```markdown
### YYYY-MM-DD: 문제 이름

- 상황과 영향:
- 확인한 원인:
- 조치와 현재 상태:
- 재발 방지 규칙:
- 검증 방법과 결과:
```

## 기록

### 2026-10-13: 서비스 정책 문서와 통합 스펙의 역할을 합침

- 상황과 영향: 별도의 정책 관리와 PRD·IA·Tech Spec 통합을 요청받았지만, 두 요청을 합쳐 모든 스펙을 `docs/policy/`에 두도록 구성했습니다. 사용자가 정책 관리 요구가 어디에 반영됐는지 다시 확인해야 했습니다.
- 확인한 원인: 문서 종류를 통합하라는 요청을 문서의 목적까지 합치라는 의미로 해석했습니다.
- 조치와 현재 상태: `docs/policy/`는 서비스 규칙과 의도·근거, `docs/specs/`는 주제별 통합 구현 명세로 분리했습니다. 스펙에서 정책 원본을 참조하도록 지침과 양식을 수정했습니다.
- 재발 방지 규칙: 사용자가 구분한 문서의 책임을 먼저 확인합니다. PRD·IA·Tech Spec의 통합과 정책 기록의 독립성을 함께 유지하고, 정책 본문은 중복 정의하지 않습니다.
- 검증 방법: 정책 관리 안내, 스펙 양식, 문서 목록, 에이전트 지침에서 두 문서의 역할과 참조 경로가 일치하는지 확인합니다.

### 2026-10-13: 린트 검증 중 의도하지 않은 의존성 설치 시작

- 상황과 영향: `.gitignore` 변경 검증 중 `expo lint`를 비대화형으로 실행했습니다. ESLint가 없는 상태에서 자동 설치가 시작돼 `package.json`에 의존성이 추가됐습니다.
- 확인한 원인: 검증 명령이 초기 설정까지 수행할 수 있다는 점을 확인하지 않았습니다.
- 조치와 현재 상태: 설치를 중단하고 해당 실행이 추가한 의존성만 제거했습니다. ESLint는 여전히 미설정이며 lint는 미검증 상태입니다.
- 재발 방지 규칙: 검증 전에 도구와 설정의 유무를 확인합니다. 미설정 상태에서 자동 설치를 유발하는 비대화형 실행을 피하고, 이번 작업에 포함되지 않은 환경 설정을 임의로 추가하지 않습니다.
- 검증 방법과 결과: 이후 대화형 실행에서 설치를 거절하자 `ESLint is not configured for this project.`로 종료됐습니다. 검증 전후 `package.json`, 잠금 파일, 설정 파일의 diff를 확인합니다.

### 2026-10-13: 전역 Git 제외 규칙으로 공통 지침이 공유 대상에서 빠짐

- 상황과 영향: 프로젝트 루트에 `AGENTS.md`와 `CLAUDE.md`가 있었지만 Git 상태에 나타나지 않아, 초기 푸시에 포함되지 않았습니다.
- 확인한 원인: 이 PC의 전역 Git 제외 파일이 두 이름을 제외하고 있었습니다.
- 조치와 현재 상태: 프로젝트 `.gitignore`에 두 루트 파일의 예외 규칙을 추가했고, Git 상태에서 새 파일로 표시되는 것을 확인했습니다. 원격 반영 여부는 커밋·푸시할 때 별도로 확인해야 합니다.
- 재발 방지 규칙: 문서가 로컬에 존재하는 것과 Git으로 공유된 것을 구분합니다. 새 문서는 Git 상태를 확인하고, 보이지 않으면 `git check-ignore -v <경로>`로 원인을 찾습니다.
- 검증 방법: 커밋 전에는 `git status --short`, 커밋 후에는 `git ls-files AGENTS.md CLAUDE.md`로 확인합니다. 다른 PC에서는 푸시된 브랜치를 가져온 뒤 파일을 확인합니다.
